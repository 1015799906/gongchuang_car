# GCS 金奖赛项——物流搬运机器人 核心代码解析文档

## 一、项目概述

### 1.1 项目背景
本项目是一台**物流搬运竞赛机器人**的控制系统，参加的是"金奖"级别的机器人竞赛。机器人需要完成以下任务：
1. **二维码识别**：扫描场地二维码获取任务序列
2. **物块搬运**：从物料平台上抓取红/绿/蓝色物块，按任务要求放置到色环或码垛区域
3. **色环定位**：在地面色环上进行精细定位和放置
4. **码垛任务**：将物块精确堆叠

### 1.2 整体架构

```

│  上位机: RDK X5 (树莓派级SBC)    │
│  Python + OpenCV 视觉处理        │

           │ UART (USART1, 115200)
```

## 二、下位机固件 (STM32F407) 核心代码详解

### 2.1 系统启动流程 (`Core/Src/main.c`)

```
上电
  → HAL_Init()                    // 复位外设、初始化Flash和SysTick
  → SystemClock_Config()          // 配置168MHz主频 (HSE 8MHz × PLL)
  → MX_GPIO_Init()                // 初始化LED引脚
  → MX_CAN1_Init()                // CAN1: 500Kbps, 与电机驱动器通信
  → MX_TIM2/3/4/5/6_Init()        // 定时器初始化
      TIM2: 舵机PWM (CH2夹爪, CH3置物盘, CH4云台)
      TIM3: 加热控制PWM (CH1)
      TIM4: 50ms周期PID控制
  → MX_UART5_Init()               // 调试日志口 (DBG_UART)
  → MX_USART1_UART_Init()         // 上位机通信口 (HOST_UART)
  → MX_USART2_UART_Init()         // IMU传感器口
  → MX_USART6_UART_Init()         // HMI串口屏
  → host_init()                   // 武装上位机接收中断
  → race_chassis_init()           // 底盘/执行器初始化 (详见2.3)
  → race_wait_host_ready()        // 等待上位机握手 "987654321"
  → race_wait_switch()            // 等待物理开关释放
  → 主循环: race_task_run()       // 比赛任务序列 (详见2.7)
```

**关键中断回调：**
- `HAL_UART_RxCpltCallback`：分发到上位机协议处理 (`host_isr_rx_cplt`) 或 IMU处理 (`imu_uart2_rx_cplt`)
- `HAL_CAN_RxFifo0MsgPendingCallback`：电机CAN反馈数据入环形缓冲区
- `HAL_TIM_PeriodElapsedCallback` (TIM4)：触发50ms周期的PID姿态控制

### 2.2 上位机通信协议 (`Core/Src/host_proto.c`)

**物理层：** USART1 (PA9/PA10), 115200bps

**帧格式 (上位机 → STM32):**
```
| 0xFF | 9字节ASCII载荷 | 0xFE |
  帧头                      帧尾
```

**例：**
- 握手帧：`0xFF 39 38 37 36 35 34 33 32 31 0xFE` ("987654321")
- 检测失败：`0xFF 30 30 30 30 30 30 30 30 34 0xFE` ("000000004")
- 坐标结果：`0xFF 30 39 35 35 30 35 31 39 31 0xFE` ("095505191") → x=0955, y=0519, color=1

**帧格式 (STM32 → 上位机):**
- 单字节ASCII命令，不补换行
- 上位机通过 `pyserial readline()` + `timeout=0.1s` 接收

**收包状态机 (`host_on_rx_byte`):**
```
State 0 → 等帧头 0xFF
State 1 → 收9字节载荷
State 2 → 等帧尾 0xFE → 置位 s_rx_flag
```

**关键API:**
| 函数 | 用途 |
|------|------|
| `host_init()` | 复位状态机，武装单字节接收中断 |
| `host_isr_rx_cplt()` | 中断回调：处理接收字节 + 重新武装 |
| `host_get_rx_flag()` | 主循环轮询：有新包返回1（读后清零） |
| `host_rx_copy(out)` | 拷贝9字节载荷 |
| `host_send_byte(b)` | 发送单字节命令到上位机 |
| `host_is_handshake()` | 判断是否握手帧 "987654321" |

### 2.3 底盘与执行器控制 (`Core/Src/race_chassis.c`)

这是整个下位机**最核心、最复杂**的模块，约1190行代码。

#### 2.3.1 CAN电机通信层

所有电机（4个底盘电机 + 升降 + 平推）通过CAN总线使用 **ZDT协议** 控制。

**硬件层 (`Core/Src/hal_zdt.c`)：**
- CAN1扩展帧，29位ID = `(addr << 8) | pack_number`
- 所有CAN命令以 `0x6B` 结尾
- 命令类型：
  - `0xF3` → 使能电机
  - `0xF6` → 速度模式 (dir + vel + acc)
  - `0xFD` → 位置模式 (dir + vel + acc + 脉冲数)
  - `0xFE` → 停止
  - `0xFF` → 同步启动
  - `0x9A` → 触发回零
  - `0x4C` → 配置回零参数
  - `0x0A` → 清除位置计数

#### 2.3.2 底盘运动控制

**电机布局 (麦克纳姆轮):**
```
电机2(前左) ←     → 电机1(前右)
     \   车头方向    /
      [ 机器人本体 ]
     /              \
电机3(后左) ←     → 电机4(后右)
```

**速度解算 (`car_move`):**
```c
speed[1] = +v_x + v_y - w;  // 前右
speed[2] = -v_x + v_y + w;  // 前左
speed[3] = -v_x + v_y - w;  // 后左
speed[4] = +v_x + v_y + w;  // 后右
```

**运动函数族：**

| 函数 | 功能 |
|------|------|
| `car_move(vx, vy, w)` | 开环速度控制 |
| `car_move_distance_x(x)` | 纯X方向位置移动 (mm→脉冲: ×10.5) |
| `car_move_distance_y(y)` | 纯Y方向位置移动 (mm→脉冲: ×10.3) |
| `car_move_distance(x, y, acc, speed)` | 通用位置移动 (先Y后X) |
| `car_move1(x, y, acc, speed)` | Y方向移动并等待完成 |
| `car_move2(x, y, acc, speed)` | X方向移动并等待完成 |

#### 2.3.3 PID姿态控制

**PID结构体：**
```c
typedef struct {
    float kp, ki, kd;
    float error, lastError, integral;
    float maxIntegral;  // 积分限幅 = 7.0
    float maxOutput;    // 输出限幅 = 180.0 (默认) / 30.0 (低输出)
} PID;
```

**角度误差处理：** 处理 -180°/180° 环绕问题
```c
if (error < -180) error += 360;
else if (error > 180) error -= 360;
```

**5种PID参数配置 (`PID_move` 的 `pid_choose`):**

| Profile | kp | ki | kd | 用途 |
|---------|----|----|----|------|
| 0 (TRANSIT) | 2.0 | 0.0 | 0.8 | 大角度转场 |
| 1 (LOW_OUTPUT) | 3.3 | 0.0 | 1.8 | 低功率运动 |
| 2 | 5.0 | 0.0 | 5.0 | 快速响应 |
| 3 (SETTLE_KI_LOW) | 2.0 | 0.05 | 0.4 | 稳态小积分 |
| 4 (SETTLE_KI_HIGH) | 2.0 | 0.07 | 0.4 | 稳态大积分 |

**PID执行流程：**
```
PID_move(vx, vy, w, time, target_angle, profile)
  → 配置PID参数
  → PID_DIL() 设置目标值
  → 启动TIM4中断 (50ms周期)
  → 循环等待:
      每个50ms: imu_scan() 读取角度
              → PID_Calc() 计算输出
              → car_move() 应用到电机
  → 达到时间或flag置位后停止
```

#### 2.3.4 执行器控制

**平推机构 (PINGTUI, 电机6):**
- 毫米→脉冲：`pulses = mm × 25.465`
- 范围：0~65mm
- 0=回收安全位, 10=放置伸出位, 50=抓取位, 65=最大

**升降机构 (SHENGJIANG, 电机5):**
- 毫米→脉冲：`pulses = mm × 80`
- 范围：0~60mm
- 0=最上方安全位, 10=转移高度, 60=放置/抓取高度

**回零流程 (`shengjiang_homezero_run`):**
```
1. 清除CAN接收缓冲区
2. 清除堵转标志
3. 使能电机
4. 配置传感器less回零 (模式2, 方向1)
5. 触发回零
6. 轮询等待:
   - 检查回零状态 (0x3B回复)
   - 同时监控速度和相电流作为备用判定
7. 成功后清除驱动位置 + 软件位置
```

#### 2.3.5 舵机控制

**3路PWM舵机 (TIM2):**

| 通道 | 名称 | 功能 | 角度范围 |
|------|------|------|----------|
| CH2 | 夹爪 (ZH) | 合爪25°/开爪50° | 0~270° |
| CH3 | 置物盘 (PT) | 3位旋转料盘 | 0°/135°/270° |
| CH4 | 云台 (YT) | 末端旋转 | 0~360° |

**软启动：** 所有舵机通过增量步进方式移动，避免突变抖舵
```c
set_servo_pwm_slow(channel, current, target, step, delay_ms)
// YT: step=10, delay=20ms
// PT: step=20, delay=10ms
```

### 2.4 IMU传感器 (`Core/Src/imu.c`)

使用 **维特智能 (WitMotion)** IMU模块，通过USART2连接。

**初始化：**
- 波特率115200，协议类型 `WIT_PROTOCOL_NORMAL`
- 寄存器回调 `SensorDataUpdata` 追踪加速度/角速度/角度更新
- 数据存储在SDK全局数组 `sReg[]`

**数据获取 (`imu_scan`):**
```c
// 加速度: sReg[AX+i] / 32768 × 16g
// 角速度: sReg[GX+i] / 32768 × 2000°/s
// 欧拉角: sReg[Roll+i] / 32768 × 180°
fAngle[2]  // Yaw角，用于PID姿态控制的反馈量
```

### 2.5 IO和辅助功能 (`Core/Src/race_io.c`)

| 功能 | 实现 |
|------|------|
| LED指示 | PF9(LED0) / PF10(LED1) |
| 开关读取 | PC9, 低电平触发 |
| 上位机通信 | 通过 host_proto 模块转发 |
| HMI串口屏 | USART6, HMISends/HMISendb |

### 2.6 底盘标定工具 (`Core/Src/chassis_calib.c`)

一个独立的单字符命令系统，通过DBG_UART (UART5) 接收命令，用于调试：

- `0` = 全部停止
- `1/2/3/4` = 单个电机速度测试
- `V/W` = 整车前进/旋转
- `X/Y/x/y` = 位置移动±100mm
- `P/Q` = 读取位置/速度
- `T/t` = 云台微调±5 PWM
- `G/g` = 夹爪微调±20 PWM
- `L/l/M/m/N/n/O/o` = 各种舵机预设位置

### 2.7 比赛任务序列 (`Core/Src/race_task.c`)

**这是整个项目最关键的逻辑文件**，定义了完整的比赛流程。约683行。

#### 2.7.1 任务码解析

上位机下发 `0xFF + task_order(7位ASCII) + 0xFE`
例：`"132+312"` → task[0..2]=[1,3,2] 第一圈, task[3..5]=[3,1,2] 第二圈

#### 2.7.2 视觉命令协议

| 命令 | 含义 | 超时 |
|------|------|------|
| `0x31` ('1') | 识别二维码获取任务序列 | 20s |
| `0x32` ('2') | 第一块物块粗定位+颜色 | 15s |
| `0x33` ('3') | 第一圈转盘物块颜色编码 | 20s |
| `0x34` ('4') | 第二圈转盘物块颜色编码 | 20s |
| `0x35` ('5') | 验证第一圈第2个物块颜色 | 30s |
| `0x36` ('6') | 验证第一圈第3个物块颜色 | 30s |
| `0x37` ('7') | 色环粗定位 | 10s |
| `0x38` ('8') | 色环精细定位 | 10s |
| `0x39` ('9') | 码垛粗定位 | 10s |
| `0x61` ('a') | 第二圈首个物块初始检测 | 15s |
| `0x62` ('b') | 第二圈验证第2个物块颜色 | 30s |
| `0x63` ('c') | 第二圈验证第3个物块颜色 | 30s |

#### 2.7.3 颜色编码

| 颜色 | 编码 |
|------|------|
| 红 (Red) | '1' |
| 绿 (Green) | '2' |
| 蓝 (Blue) | '3' |
| 未检测到 | '4' (MISS) |

#### 2.7.4 坐标转换

**物块坐标 (上位机发送9字节):**
```
{xxxx}{yyyy}{color} → 例: "095505191"
x = bytes[0..3] as decimal, y = bytes[4..7] as decimal, color = bytes[8]

转换→实际距离:
  bilichi = -0.0035×(distance+80) + 1.1967  (task1)
  bilichi = -0.0033×distance + 1.1655        (task2)
  direct_x = (x_origin - 322) × bilichi       (减去摄像头偏移)
  direct_y = (y_origin - 165) × bilichi
```

**色环坐标:**
```
粗定位(分辨率1): direct = (origin - center) × 1.1805555
精定位(分辨率2): direct = (origin - center) × 0.29239766
  red_center:   (955, 519)
  green_center: (955, 519)
  blue_center:  (955, 519)
```

**颜色偏移校正：**
根据物块颜色和目标位置联动偏移 `distance_wukuai = 150mm`

#### 2.7.5 完整任务流程

```
race_task_run()
  │
  ├─[阶段1] race_stage_read_task_order()
  │  发送'1'→上位机识别二维码→获取6位任务码
  │  前移150mm→后退530mm→等待上位机返回任务序列
  │
  ├─[阶段2] race_stage_prepare_actuators()
  │  执行器归零→加热开启→后退910mm→云台转120°
  │
  ├─[阶段3] race_stage_pick_first_platform_blocks()
  │  视觉定位物块→移动到位→识别3个物块颜色编码
  │  →依次抓取到置物盘3个工位(带颜色验证重试)
  │
  ├─[阶段4] race_stage_first_ring_task012()
  │  移动至色环区→粗定位→精定位→按任务码放置3个物块
  │  →取回3个物块(再次到置物盘)
  │
  ├─[阶段5] race_stage_second_ring_task012()
  │  重复色环流程→第二次放置3个物块(不取回)
  │
  ├─[阶段6] race_stage_pick_second_platform_blocks()
  │  移动至第二物料区→定位→识别颜色编码→抓取3个物块
  │
  ├─[阶段7] race_stage_third_ring_task345()
  │  色环区第三圈→放置后取回(对应task[3..5])
  │
  ├─[阶段8] race_stage_fourth_ring_task345()
  │  码垛区→定位→放置(不取回)
  │
  └─[阶段9] race_stage_finish_drive()
     最终行驶至终点区→race_finish_stop()停止
```

#### 2.7.6 关键动作原语

**基本运动 + 执行器组合:**

| 函数 | 功能 |
|------|------|
| `act_pose(ping, lift, yaw)` | 三轴联动 (平推+升降+云台) |
| `act_safe_transfer()` | 转移到安全转移位 (ping=0, lift=10, yaw=0) |
| `act_pick_current_platform()` | 当前置物盘工位抓取 |
| `act_release_to_yaw(yaw)` | 放置物块到指定角度 |
| `act_pick_from_yaw(yaw)` | 从指定角度抓取物块 |
| `act_current_platform_to_yaw(code)` | 完整抓取→搬运→放置循环 |

**组合动作序列:**
- `fangzhi(code)` = 放置物块到code对应的环位置
- `na(code)` = 从code对应的环位置拿取物块
- `yuantai_na(code)` = 完整动作：从置物盘取物块放到环上

**环角度映射:**
```
code 1 → 90°  (右环)
code 2 → 120° (中心环)
code 3 → 150° (左环)
```

#### 2.7.7 安全机制

1. **超时保护：** 所有 `wait_send_shumeipai()` / `wait_rx_ms()` 有超时，超时后调用 `race_host_timeout_stop()` → 停止所有执行器 + 闪烁LED
2. **视觉重试：** 检测到 MISS 时循环重试
3. **运动完成等待：** 所有位移运动都计算运动时间并等待
4. **加热控制：** 仅在需要抓取/放置时开启加热(300 PWM)，转移时关闭

## 三、上位机视觉程序 (Python/OpenCV) 核心代码详解

### 3.1 程序入口与架构

`host_main.py` 运行在 **RDK X5** (或开发时Windows PC)上。

**主入口 (`main`):**
```python
parser → --qr / --ring / --ring-centered / --maduo / --maduo-centered
       → 调试预览模式
默认 → HostSerialCommandHandler().run()  # 正常比赛模式
```

**正常比赛模式 (`HostSerialCommandHandler.run`):**
```
1. 打开串口 (GCS_HOST_SERIAL, 默认 /dev/ttyS1)
2. 发送握手帧 "987654321"
3. 循环: receive_data() → handle_serial_data(command)
```

### 3.2 通信协议实现

**发送数据 (`send_data` → `build_data_packet`):**
```python
payload = str(data).encode("ascii")
payload = payload[:9].ljust(9, b"\x00")     # 补齐9字节
return bytes([0xFF]) + payload + bytes([0xFE]) # 加帧头帧尾
```

**接收数据 (`receive_data`):**
```python
port.readline().decode("utf-8").strip()
# 上位机用 readline() + timeout=0.1s 读单字节命令
```

### 3.3 摄像头管理

| 环境变量 | 默认值 | 用途 |
|----------|--------|------|
| `GCS_QR_CAMERA` | `/dev/video_xia0` | 二维码识别摄像头 |
| `GCS_UPPER_CAMERA` | `/dev/video_shang0` | 上方全局摄像头 |
| `GCS_CAMERA_BACKEND` | `v4l2`(Linux) / `dshow`(Win) | 摄像头后端 |

**摄像头后端选择 (`select_camera_backend`):**
- Linux: CAP_V4L2
- Windows: CAP_DSHOW
- 可通过 `GCS_CAMERA_BACKEND` 覆盖: `any` / `v4l2` / `dshow` / `msmf`

### 3.4 视觉任务详解

#### 3.4.1 二维码识别 (`run_erweima`)

**触发命令: '1' (0x31)**

流程:
```
1. 打开CAMERA_QR_DEVICE
2. 循环读取帧:
   a. 转灰度图
   b. 优先使用 pyzbar 解码 (支持更多格式)
   c. 降级到 OpenCV QRCodeDetector
   d. 过滤7字符长度数据
   e. 连续3次相同 → 确认有效
3. 发送9字节数据 (7字符+补零)
4. 失败则发送 "000000004"
```

#### 3.4.2 物块检测 (`run_wukuaiyuanxin_1` / `run_wukuaiyuanxin_2`)

**触发命令: '2' / 'a'**

核心算法: Hough圆检测 + HSV颜色识别

```
1. 设置摄像头 640×480
2. ROI区域: [120,80,400,217] 或 [220,80,200,200]
3. 每帧处理:
   a. ROI内灰度化 + 高斯模糊(kernel=9)
   b. HoughCircles: minR=35, maxR=45, param1=25, param2=25
   c. 对检测到的圆:
      - 创建圆形mask
      - HSV颜色空间转换
      - 计算红/绿/蓝三色掩膜面积(带形态学开闭运算)
      - 最大面积→确定颜色编码
4. 稳定性验证:
   - 位置: 连续30帧位移<10px
   - 颜色: 15帧历史中某颜色占比>70%
5. 发送: {x:04}{y:04}{color}{radius:01}
```

#### 3.4.3 颜色编码检测 (`run_wukuaiyuanxin_A`)

**用于快速扫描置物盘的A1/A2/A3工位**

流程:
```
1. 对3个ROI区域独立检测
2. 只检测颜色(不做圆检测):
   - 直接对整个ROI做三通道颜色面积统计
   - 形态学操作→最大面积颜色
3. 容错:
   - 超时200ms未检测到→重试
   - A1==A2时→重新检测
   - A3通过排除法推断 (A3 = {1,2,3} - {A1,A2})
5. 判断旋转方向:
   is_clockwise = (A1 == C_1)  // C_1为第一圈初始物块颜色
```

#### 3.4.4 转盘逻辑 (`LOOP1` / `LOOP2`)

用于判断置物盘旋转后物块的目标位置。

```
LOOP1():
  检测第二个物块颜色C_2
  if C_1 != C_2:
    转盘已转→根据旋转方向计算索引
  else:
    循环等待直到颜色变化
  → 发送索引数据: "{INDEX}{INDEX1}{INDEX2}456789"
```

#### 3.4.5 色环定位 (`run_sehuanyuanxin2` / `run_sehuanyuanxin2_centered`)

**触发命令: '7' (粗定位) / '8' (精定位)**

两阶段精确定位策略:

**第一阶段 (粗定位, 640×480):**
```
- 搜索半径: 35~38px
- 检测区域: 433×222~240px中心区域
- 颜色+位置双稳定验证
- 输出坐标供STM32粗定位移动
```

**第二阶段 (精定位, 1920×1080):**
```
- 搜索半径: 160~165px
- 检测区域: 500×500px中心区域
- 更高分辨率实现更精细定位
- 容错: 8秒总超时, 颜色置信度0.7
```

#### 3.4.6 码垛检测 (`run_maduoyuanxin2` / `run_maduoyuanxin2_centered`)

**触发命令: '9' (粗定位) / '0' (精定位)**

与色环类似但检测参数不同:
```
- 搜索半径: 20~27px (物块比色环小)
- 检测区域更大: 600×200~300px
- 位置稳定性要求更高: stable_count ≥ 4
```

#### 3.4.7 直线纠偏 (`detect_boundary_line`)

**触发命令: 无直接命令 ('d' 直接返回 "000000000")**

用于检测场地边界线角度来做姿态纠偏:
```
1. 1920×1080高分辨率
2. Canny边缘检测 (50/150)
3. HoughLinesP直线检测
4. 收集3次有效角度→计算方差异常值
5. 方差≤1.0→发送角度数据 (0.1°精度, 范围±9.9°)
6. 最多10次重试
```

### 7.4 注意事项

1. **CAN通信：** 所有电机命令末尾必须带 `0x6B`，地址不能冲突
2. **回零方向：** 首次部署需确认升降/平推的回零方向，方向反立即断电
3. **置物盘初始位置：** 上电后必须保证置物盘在0°（POS1）
4. **舵机PWM范围：** 严格500~2500us，超出可能烧舵机
5. **上位机超时：** 上位机有300秒无数据警告，通信中断会触发 STM32 超时锁定
6. **坐标映射约定：** 上位机发送的x/y是图像坐标(左上角原点)，STM32侧需转换为世界坐标
