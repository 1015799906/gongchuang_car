# 文件1: motor_ack_test.c（~3050行）调车交互主程序

## 框架

```
┌─ 常量宏定义（第15~89行）
├─ 全局变量（第91~130行）
├─ 基础工具函数（输出/解析）
├─ 舵机层函数
├─ CAN收发层函数
├─ 运动控制函数（底盘/平推/升降）
├─ 回零函数（HOMEZERO全流程）
├─ 命令处理函数（handle_xxx）
├─ 顶层命令分发 handle_line()
├─ 主循环入口: init / poll / uart_rx / can_rx
└─ 动作组函数（act_xxx 系列）
```

## 逐函数

### 第1层：基础工具函数

**`txs(s)`** — 通过UART5发字符串到串口终端
- 就是你串口助手看到的那些 `# SJ HOMEZERO START...`

**`txu(value)`** / **`txi(value)`** — 输出无符号/有符号整数

**`tx_float3(value)`** / **`tx_fixed3(value)`** — 输出浮点数（保留3位小数）

**`tx_hex8(value)`** / **`tx_hex32(value)`** — 输出十六进制

**`trim_left(&s)`** / **`trim_right(s)`** — 去字符串首尾空格

**`starts_with(s, prefix)`** — 判断字符串是否以某前缀开头
- 命令匹配全靠它：`starts_with(cursor, "HOMEZERO")`

**`parse_i32(&cursor, &out)`** — 从字符串里解析一个整数
- 例：`"10 600 80"` → 先解析出 `10`，cursor 移动到 `"600 80"`

**`parse_float(&cursor, &out)`** — 同上，解析浮点数

**`parse_scaled(&cursor, &out)`** — 解析带小数点的 PID 参数
- 例：`"P:1.5"` → `1500`（内部 ×1000 存为整数）

### 第2层：舵机函数

**`servo_pulse_270(angle)`** — 角度 → PWM值（0~270° → 500~2500μs）

**`clamp_servo_pwm(value)`** — PWM值限幅在 500~2500 之间

**`yuantai_pwm_from_angle(angle)`** — 云台角度 → PWM（360°范围，带 7.9°偏移校准）

**`servo_apply()`** — 把三个舵机的软件PWM值一次性写入硬件寄存器
- 这是真正让舵机动起来的那一步

**`servo_dump()`** — 输出当前三个舵机的PWM值到串口

**`servo_set_pwm(channel, value)`** — 设某个舵机PWM并立即生效（无软启动）

**`servo_set_pwm_slow(channel, value)`** — **带软启动**的PWM设置
- 每步改 10μs，间隔 20ms，平滑过渡，防止舵机抖

**`servo_defaults()`** — 把三个舵机复位到默认PWM值（夹爪862/置物盘500/云台500）

### 第3层：CAN收发

**`emit_can_frame(frame)`** — 把收到的CAN帧格式化打印到串口
- 就是你看到的 `# CAN RX EXT id=0x00000500 addr=5 pack=0 dlc=3 data=3A 03 6B`
- 还会自动解析VEL帧(0x35)和POS帧(0x36)，直接打印速度/位置

**`pop_can_frame(&out)`** — 从环形缓冲区弹出一帧CAN数据
- 关中断保护，线程安全

**`emit_can_events()`** — 主循环调用，每轮最多打印4帧CAN数据
- 防止CAN帧太多刷屏

**`drain_can_for_llm()`** — LLM调参模式专用，清空CAN缓冲区

### 第4层：运动控制

**`wheel_forward_dir(id)`** — 返回指定电机的正转方向（电机1/2方向0，电机3/4方向1）

**`wheel_vel(id, speed)`** — 让单个底盘电机以指定速度转
- 自动处理正反转的方向切换

**`move_vel(vx, vy, w)`** — **麦克纳姆轮速度解算** + 四轮驱动
- 输入：期望的X速度、Y速度、旋转角速度
- 输出：通过CAN给4个轮子发速度指令

**`stop_all_motion()`** — 底盘停 + 取消所有自动停止定时器

**`zdt_stop_repeat(addr)`** — 连发3次停止指令给某电机（确保停住）

**`zdt_home_stop_repeat(addr)`** — 先终止回零再连发3次停止

**`zdt_home_status_read(addr)`** — 读回零参数(0x22) + 回零状态(0x3B)

### 第5层：升降电机专用

**`shengjiang_upzero_run(ms, speed, acc)`** — 限时轻顶归零
- 向顶部方向转 `ms` 毫秒后停止 + 清零位置
- 用于顶部附近快速归零，不需碰撞检测

**`pop_home_status(addr, &status)`** — 从CAN缓冲区筛选回零状态帧(0x3B)

**`wait_home_idle(addr, timeout_ms, &last_status)`** — **轮询等回零完成**
- 每200ms循环：读回零状态 → 查GOING位 → 位=0就完成
- 超时返回 false, status=0x04

**`shengjiang_homezero_run(dir, current_ma, time_ms, timeout_ms, &status)`** — **升降回零完整流程**
- 清堵转 → 使能 → 配回零参数 → 触发(mode=2) → 等完成 → 清零位置

**`shengjiang_homezero_default(tag)`** — 用默认参数调上面那个函数
- 开机时调用：`shengjiang_homezero_default("BOOT")`

**`zdt_home_cfg_sensorless(addr, dir, current_ma, time_ms)`** — 配置传感器less回零参数
- 内部调 `zdt_home_params_write`，mode=2

### 第6层：串口命令处理函数

**`handle_imu(cmd)`** — 处理 `IMU` 命令 → 打印当前角度

**`handle_set(params)`** — 处理 `SET P:xx I:xx D:xx` → 设置PID参数

**`handle_pid(params)`** — 同上，别名

**`handle_acc(params)`** — 处理 `ACC 160` → 设加速度

**`handle_servo(params)`** — 处理 `SERVO` 和 `SERVO 2 862`
- 无参数→打印；有参数→设置

**`handle_angle_servo(params, type)`** — 处理 `YT 90` / `PT 135` / `ZH 50`
- type='Y'→云台(360°), 'P'→置物盘(270°), 'Z'→夹爪(270°)

**`handle_shengjiang(params)`** — 处理所有 `SJ` 子命令
- `SJ` → 打印状态
- `SJ 10 600 80` → 位置控制
- `SJ STOP/EN/DIS/READ/HSTAT` → 各种操作
- `SJ HOMEZERO [dir] [mA] [ms] [timeout]` → 回零
- `SJ HCFG dir [mA] [ms]` → 配回零参数
- `SJ HSTOP/HOME/HOME3/CLEAR/UNSTALL/ZERO/SET`
- `SJ UP/UPZERO ms speed acc` → 轻顶归零

**`handle_pingtui(params)`** — 处理所有 `PUSH` 子命令
- 格式同 SJ，地址=6

**`handle_enc(params)`** — 处理 `ENC` → 读底盘四轮编码器

**`handle_wheel(params)`** — 处理 `WHEEL 1 100` → 单轮速度测试

**`handle_move(params)`** — 处理 `MOVE vx vy w` → 底盘速度矢量

**`handle_pulse(params)`** / **`handle_pulse_one(params)`** — 脉冲测试

**`handle_act(params)`** — 处理所有 `ACT` 子命令（详见动作组部分）

**`handle_llm(params)`** — 处理 `LLM ON/OFF` → 原地旋转姿态调参

### 第7层：顶层命令分发

**`handle_line(line)`** — **所有串口命令的总入口**
- 收到一行文本 → 匹配前缀 → 分发给上面的 handle_xxx
- 命令匹配表：
  ```
  "STATUS"    → emit_status()
  "RESET"     → stop_all_motion() + 恢复默认参数
  "ENC"       → handle_enc()
  "IMU*"      → handle_imu_xxx()
  "SET ..."   → handle_set()
  "PID ..."   → handle_pid()
  "ACC ..."   → handle_acc()
  "SERVO ..." → handle_servo()
  "YT ..."    → handle_angle_servo()
  "PT ..."    → handle_angle_servo()
  "ZH ..."    → handle_angle_servo()
  "SJ ..."    → handle_shengjiang()
  "PUSH ..."  → handle_pingtui()
  "ACT ..."   → handle_act()
  "LLM ..."   → handle_llm()
  "WHEEL ..." → handle_wheel()
  "MOVE ..."  → handle_move()
  "PULSE ..." → handle_pulse()
  ```

### 第8层：主循环

**`arm_rx()`** — 武装 UART5 单字节接收中断（每次收完一字节后需要重新武装）

**`motor_ack_test_init()`** — **上电初始化**
- 舵机PWM启动 + 默认值
- IMU/PID初始化
- CAN滤波器 + 启动
- 升降HOMEZERO（可注释掉）
- 平推清零
- 武装接收中断 + 打印状态

**`motor_ack_test_uart_rx_callback(huart)`** — UART5接收中断回调
- 逐字符收，遇 `\n` 完整一行 → 置 `s_line_ready=1`

**`motor_ack_test_poll()`** — **主循环（死循环里每次调这个）**
- 检查是否收到命令 → `handle_line()`
- 检查底盘超时自动停
- LLM调参模式下跑PID

**`motor_ack_test_can_rx_callback(hcan)`** — CAN接收中断回调
- 收到CAN帧 → 放入16槽环形缓冲区

### 第9层：动作组函数（ACT子命令的实现）

**`emit_status()`** — 打印完整状态（舵机/位置/IMU/PID/ACC）
- 就是 `STATUS` 命令的输出

**`act_pose(ping, lift, yaw)`** — 三轴联动定位

**`act_safe()`** — 安全姿态：开爪+工位1+平推0+升降0+云台0+关加热

**`act_open()`** / **`act_close()`** — 开/合爪

**`act_rack()`** — 置物架抓取准备位

**`act_pick(pos)`** — 指定工位(1/2/3)抓取

**`act_platform(pos)`** — 旋转置物盘到指定工位

**`act_heat_on()`** / **`act_heat_off()`** / **`act_heat_set(v)`** — 加热控制

**`act_round3()`** — 三工位完整抓放动作链

**`act_fang(code)`** / **`act_fangmd(code)`** — 放置物块到环/码垛区

**`act_na(code)`** — 从环区取回物块

**`act_ytna(code)`** — 圆台取物全流程

**`act_na1(code)`** / **`act_na2(code)`** — 圆台预置位/夹取

### LLM姿态调参函数

**`apply_default_llm_pid()`** — 恢复默认PID参数(kp=1.1, ki=0, kd=0)

**`apply_llm_pid(kp, ki, kd)`** — 写入自定义PID参数

**`llm_reset_state()`** — 重置PID状态（清积分/误差）

**`llm_poll(now)`** — LLM模式的主循环：读IMU → PID计算 → 底盘驱动

**`handle_llm(params)`** — 处理 `LLM ON speed yaw` 和 `LLM OFF`

**`emit_llm_csv()`** — 打印当前PID参数

# 文件2: race_chassis.c（主固件版~1190行）底盘+执行器控制

> 这是主固件(wuliu)的版本，motor_test 有自己的部分实现

## 框架

```
┌─ 数据结构 PID
├─ 全局变量（IMU数据、PID实例、状态标志）
├─ CAN层（滤波器、环形缓冲、收发）
├─ 底盘运动函数（car_move系列）
├─ PID控制函数
├─ 执行器函数（升降/平推 位置控制）
├─ 舵机函数（软启动）
├─ 联动函数（move_all 三轴联动）
└─ 初始化 race_chassis_init()
```

## 逐函数

### CAN层

**`can_filter_start()`** — 配CAN滤波器 + 启动CAN接收中断
- 不过滤任何ID（全接收）

**`race_chassis_can_rx_callback(hcan)`** — CAN接收中断 → 写入环形缓冲区

**`pop_can_frame(&out)`** — 弹一帧CAN数据（关中断）

**`clear_can_rx_ring()`** — 清空CAN缓冲区

### 底盘运动函数

**`change_A(a)`** / **`change_SNA1(a, speed)`** — 修改全局加速度和速度参数

**`car_move(vx, vy, w)`** — **麦克纳姆轮速度解算 + 四轮驱动**
- 每个轮子之间 `delay_ms1(1)` 防止 CAN 发送太密

**`car_move_distance_x(x)`** / **`car_move_distance_y(y)`**
- 纯X或纯Y方向位置移动
- X: mm→脉冲 = ×10.5, Y: mm→脉冲 = ×10.3
- 四轮同步启动（`zdt_sync(0)`）

**`car_move1(x,y,a,s)`** — 纯Y移动 + 等完成（x被忽略）
**`car_move2(x,y,a,s)`** — 纯X移动 + 等完成（y被忽略）
**`car_move3/car_move4`** — 同上但不等待
**`car_move_distance(x,y,a,s)`** — 先Y后X，各等完成

**`car_move_delay(distance, a, speed, dir)`** — **梯形速度曲线时间估算**
- 算加速段+匀速段各需多少时间
- 返回运动总时间(ms)，调用者用 `delay_ms1` 等待

### PID函数

**`PIDInit()`** — 设默认PID参数(kp=1.5, ki=0.001, kd=2.0)

**`PID_Calc(pid, ref, feedback)`** — **PID计算核心**
- 处理角度环绕（-180/180跳变）
- P项 = error × kp
- D项 = (error-lastError) × kd
- I项累加后限幅
- 总输出限幅

**`PID_DIL(vx, vy, w, time, target)`** — 设PID目标值和运动参数（不启动）

**`race_chassis_tim4_callback()`** — TIM4中断(50ms) → 置标志位

**`PID_tim4_run()`** — 50ms定时执行：IMU读角度 → PID计算 → 底盘驱动

**`PID_move(vx, vy, w, time, target, profile)`** — **PID姿态控制主函数**
- 5组profile参数切换
- 启动TIM4 → 循环等50ms中断 → 跑PID → 到时间或到位停止

### 升降电机函数

**`shengjiang_control(target, speed, accel)`** — 位置模式移动
- Δmm → 脉冲(×80) → CAN `zdt_pos`
- 软件位置 `current_pos1` 直接设为目标值（开环！偏差根因）

**`shengjiang_current_pos()`** — 读软件记录的位置

**`shengjiang_set_current_pos(pos)`** — 设软件位置

**`race_shengjiang_homezero()`** — 调 `shengjiang_homezero_run()` 回零

**`shengjiang_homezero_run(&status)`** — 回零完整流程（主固件版）
- 清缓冲→清堵转→使能→配参数→触发→轮询等完成→清零→set_pos=0

**`shengjiang_move_delay(pulses, accel, speed)`** — 运动时间估算（梯形速度）

### 平推电机函数

**`pingtui_control(target, speed, accel)`** — 位置模式
- Δmm → 脉冲(×25.465)

**`pingtui_current_pos()`** / **`pingtui_set_current_pos(pos)`** — 读/设软件位置

**`race_pingtui_clear_zero()`** — 软件+驱动器位置双清零

**`pingtui_reset()`** — 归零（移动+清零）

### 舵机函数

**`servo_pulse_270(angle)`** — 角度→PWM（0~270°→500~2500）

**`yuantai_pwm_from_angle(target)`** — 云台角度→PWM（带7.9°偏移）

**`wukuai_pwm_from_angle(target)`** — 置物盘角度→PWM

**`set_yuantai_Angle(target, time)`** — 设云台角度（软启动+等time毫秒）

**`set_zhuashou_Angle(angle, speed)`** — 设夹爪角度（无软启动，等speed毫秒）

**`set_wukuaipingtai_Angle(angle, speed)`** — 设置物盘角度（软启动+等speed毫秒）

**`set_zhuashou_he()`** — 合爪(25°)

**`set_zhuashou_kai()`** — 开爪(50°)

**`set_wukuaipingtai_weizhi(pos)`** — 置物盘到指定工位(1=0° / 2=135° / 3=270°)

**`set_servo_pwm_slow(ch, cur, target, step, delay)`** — 通用软启动

### 联动+系统

**`move_all(ping,_,_, lift,_,_, yaw,_)`** — **三轴联动**
- 平推+升降+云台同时运动
- 算各自运动时间，等最慢的那个完成
- 加速度被硬编码：`accel1=240`（升降偏大，容易丢步）

**`move_all1(...)`** — 简化版三轴联动（云台只等固定300ms）

**`race_heat_set(compare)`** — 设加热PWM（TIM3_CH1）

**`race_actuator_stop_all()`** / **`race_actuator_reset_all()`**
- stop: 全停+关加热
- reset: 开爪+盘1+云台0+平推归零+升降回零

**`race_chassis_init()`** — **底盘总初始化**
- CAN起 → 舵机PWM起 → 平推/升降清零 → 关加热 → IMU→PID→执行器归零

### 调试日志函数（`SHENGJIANG_HOMEZERO_LOG`）

**`dbg_txs/txu/txi/txh4/txh8`** — 调试输出到UART5

**`dbg_can_frame`** — 打印收到的CAN帧详情（ID/DLC/数据/解析速度/位置）

**`dbg_home_status`** — 打印HOMEZERO状态（enc/table/going/fail各标志位）

# 文件3: race_task.c（~683行）比赛流程编排

## 框架

```
┌─ 常量（角度/位置/速度/加热 宏定义）
├─ 视觉命令协议宏（VISION_CMD_xxx）
├─ 视觉结果编码宏（VISION_RESULT_xxx）
├─ PID Profile 宏
├─ 静态全局变量（task数组、坐标变量）
├─ 工具函数（超时/收包等）
├─ 坐标转换函数（图像→世界坐标）
├─ 动作原语函数（act_xxx 系列）
├─ 9个比赛阶段函数
└─ 总入口 race_task_run()
```

## 逐函数

### 工具函数

**`race_host_timeout_stop()`** — 通信超时紧急处理
- 全停 → 底盘停 → 死循环闪LED1(200ms)
- 比赛中最不想看到的东西

**`wait_rx_ms(time)`** — 等上位机发来数据包，超时返回0

**`wait_send_shumeipai(cmd, time)`** — 向上位机发一个命令字节 + 等回复

**`wait_packet_98()`** — 等上位机发来 "98" 确认包

### 坐标转换

**`transfer_position_wukuai(task_choose, distance, color)`** — **物块坐标转换**
- 上位机返回 9 字节 ASCII → 解析 x/y/color
- 比例尺公式（两个不同task用不同系数）
- 颜色修正偏移（不同颜色物块，横向偏移 `distance_wukuai=150mm`）
- MISS(颜色4) → 默认 (5,-5)

**`transfer_position_sehuan(fenbian, task_num)`** — **色环坐标转换**
- 粗定位(fenbian=1): 比例尺 1.18
- 精定位(fenbian=2): 比例尺 0.292，三种颜色各有不同中心坐标
- 同样有色偏修正

### 映射函数

**`yaw_for_code(code)`** — 环编码(1/2/3) → 云台角度(90/120/150°)

### 动作原语（组合动作的积木）

**`act_pose(ping, lift, yaw)`** — 三轴联动 → `move_all()`

**`act_zero_before_chain()`** — 动作链前归零：停→平推翻零→升降回零→开爪→盘1→安全位

**`act_safe_transfer()`** — 转移到安全位(ping=0, lift=10, yaw=0)

**`act_pick_current_platform()`** — 从当前置物盘工位抓取物块
- 开爪→伸到抓取位→合爪→抬到转移位

**`act_release_to_yaw(yaw)`** — 放到指定云台角度位置

**`act_pick_from_yaw(yaw)`** — 从指定云台角度取回

**`act_current_platform_to_yaw(code)`** — 完整抓放：从盘抓→放到环

**`act_pre_yaw(code)`** — 预置位：云台转到位置，开爪准备

### 简化命名

**`fangzhi(code)`** — 放置到环

**`fangzhi_maduo(code)`** — 码垛放置

**`na(code)`** — 从环取回

**`yuantai_na(code)`** — 圆台完整取回

**`yuantai_na1(code)`** — 圆台预置位

**`yuantai_na2(code)`** — 圆台夹取+带回

### 9 个比赛阶段

**`race_stage_read_task_order()`** — 阶段1：扫二维码
- 发'1' → 上位机扫二维码 → 解析6个任务码 → 显示到串口屏

**`race_stage_prepare_actuators()`** — 阶段2：执行器准备
- 归零→开加热→安全转移→开爪→后退910mm→云台转120°

**`race_stage_pick_first_platform_blocks()`** — 阶段3：第一平台抓取
- 发'2'定位→视觉引导移动→发'3'获取颜色编码→依次三工位抓取

**`race_stage_first_ring_task012()`** — 阶段4：色环第一圈（放+取回）
- 导航→粗定位→精定位→按task[0..2]放→取回

**`race_stage_second_ring_task012()`** — 阶段5：色环第二圈（只放不取）

**`race_stage_pick_second_platform_blocks()`** — 阶段6：第二平台抓取

**`race_stage_third_ring_task345()`** — 阶段7：色环第三圈

**`race_stage_fourth_ring_task345()`** — 阶段8：码垛区

**`race_stage_finish_drive()`** — 阶段9：终点区导航→停车

### 总入口

**`race_task_run()`** — **比赛全部9阶段，按顺序执行**
- 是一条直线调用链，没有分支、没有循环
- 每个阶段出故障 → 内部就 `race_host_timeout_stop()` 了，不会到下一阶段

**`race_finish_stop()`** — 完赛停止
- 执行器归零→关加热→底盘停→死循环慢闪LED(500ms)

# 文件4: host_proto.c（~177行）上位机通信协议

## 框架

```
┌─ 接收缓冲区（volatile, 中断和主循环共享）
├─ 状态机 host_on_rx_byte()
├─ 公开API函数
└─ 辅助函数
```

## 逐函数

**`host_init()`** — 初始化：清标志/缓冲区 + 武装 USART1 单字节接收中断

**`host_isr_rx_cplt()`** — 中断回调（在 `HAL_UART_RxCpltCallback` 里调）
- 拿刚收到的字节 → 推进状态机 → 重新武装中断

**`host_on_rx_byte(b)`** — **三级状态机**
```
State 0: 等 0xFF → 收到 → State 1
State 1: 收 9 字节 → 收满 → State 2
State 2: 等 0xFE → 收到 → s_rx_flag=1, 回 State 0
           不是 0xFE → 停在 State 2 继续等（不重置）
```

**`host_get_rx_flag()`** — 主循环轮询：有新包返回1（读后自动清零）

**`host_rx_at(i)`** — 读载荷第 i 字节（0~8）

**`host_rx_copy(out)`** — 拷出全部 9 字节到 `out` 数组

**`host_send_byte(b)`** / **`host_send_cmd(c)`** — 发单字节到上位机（阻塞）

**`host_send_string(s)`** — 发字符串（到 `\0`）

**`host_is_handshake()`** — 当前包 == "987654321" ?

**`host_packet_eq(s)`** — 当前包 == 给定 9 字串？

# 文件5: hal_zdt.c（~399行）CAN电机驱动协议

## 框架

```
┌─ 全局快照变量（最后发送的CAN帧信息，用于调试）
├─ zdt_snap() — 记录快照
├─ zdt_wait() — 等发送完成
├─ zdt_tx() — CAN发送核心
├─ 公开API: en/vel/pos/stop/sync/read/home/clear...
└─ 调试函数: last_id/dlc/box/tsr/esr/msr/dat
```

## 逐函数

**`zdt_set_wait_enabled(en)`** / **`zdt_wait_enabled()`** — 设置/读取是否等发送完成

**`zdt_snap(id, dlc, box, data)`** — 记录最后发送的CAN帧快照（调试用）

**`zdt_wait(mbox)`** — 等指定邮箱的发送完成，超时50ms返回错误

**`zdt_tx(cmd, len)`** — **CAN发送核心**
- 自动分包：如果数据>7字节，拆多帧，每帧 `pack` 递增
- 格式：`cmd[0]=地址, cmd[1]=功能码, 最后字节=0x6B`
- 扩展帧ID = `(addr << 8) | pack`

### 公开 API

| 函数 | CAN功能码 | 作用 |
|------|-----------|------|
| **`zdt_en(addr, on, sync)`** | 0xF3 | 使能/失能电机 |
| **`zdt_vel(addr, dir, vel, acc, sync)`** | 0xF6 | 速度模式 |
| **`zdt_pos(addr, dir, vel, acc, clk, abs, sync)`** | 0xFD | 位置模式 |
| **`zdt_stop(addr, sync)`** | 0xFE | 急停 |
| **`zdt_sync(addr)`** | 0xFF | 同步启动（之前缓冲的全部同时开始） |
| **`zdt_read(addr, reg)`** | 各有不同 | 读指定寄存器 |
| **`zdt_origin_set(addr, save)`** | 0x93 | 设当前位置为原点 |
| **`zdt_home_trigger(addr, mode, sync)`** | 0x9A | 触发回零 |
| **`zdt_home_abort(addr)`** | 0x9C | 中止回零 |
| **`zdt_home_params_read(addr)`** | 0x22 | 读回零参数 |
| **`zdt_home_params_write(addr, ...)`** | 0x4C | 写回零参数（20字节全配） |
| **`zdt_clear_pos(addr)`** | 0x0A | 清位置计数器 |
| **`zdt_clear_stall(addr)`** | 0x0E | 清堵转保护 |
| **`zdt_stop_all()`** | — | 依次停电机1~4 |

### 调试函数

| 函数 | 返回值 |
|------|--------|
| `zdt_last_id()` | 最后发送的CAN ID |
| `zdt_last_dlc()` | 最后发送的DLC |
| `zdt_last_box()` | 最后使用的邮箱号 |
| `zdt_last_tsr()` | CAN TSR寄存器快照 |
| `zdt_last_esr()` | CAN ESR寄存器快照 |
| `zdt_last_msr()` | CAN MSR寄存器快照 |
| `zdt_last_dat(i)` | 最后发送数据的第i字节 |

# 文件6: imu.c（~126行）IMU传感器驱动

## 框架

```
┌─ 常量（更新标志位宏）
├─ 全局变量（接收计数、数据更新标志）
├─ 初始化 imu_init()
├─ 中断回调 imu_uart2_rx_cplt()
├─ 数据读取 imu_scan()
└─ SDK回调函数
```

## 逐函数

**`imu_init()`** — 初始化维特智能IMU
- `WitInit(NORMAL, 0x50)` — 普通协议，地址0x50
- 注册三个回调：串口发送、数据更新、延时
- USART2波特率初始化为115200

**`Usart2Init(baud)`** — 动态改USART2波特率 + 武装接收中断

**`imu_uart2_rx_cplt()`** — USART2接收中断
- 收到一个字节 → 喂给SDK解析器 `WitSerialDataIn()`
- 重新武装接收中断

**`imu_scan(fAcc, fGyro, fAngle)`** — **读IMU数据**（PID主循环50ms调一次）
- 检查数据更新标志
- 转换公式：
  ```
  加速度: sReg[AX+i] / 32768 × 16g
  角速度: sReg[GX+i] / 32768 × 2000°/s
  欧拉角: sReg[Roll+i] / 32768 × 180°
  ```
- fAngle[2] = Yaw → PID反馈的核心输入
- 读完清标志

**`Uart2Send(data, size)`** — SDK回调：向IMU模块发送配置命令

**`SensorUartSend(data, size)`** — SDK内部用的发送包装

**`Delayms(ms)`** — SDK回调：延时

**`SensorDataUpdata(reg, regNum)`** — SDK回调：IMU有数据更新
- 根据寄存器类型设置对应的更新标志
- Yaw更新 → `ANGLE_UPDATE` → `s_angle_update_count++`

**`imu_rx_count()`** / **`imu_update_count()`** / **`imu_angle_update_count()`** — 返回各种计数值（调试用）
