## 一、项目概述

### 1.1 这是一个什么项目

一台**全自动智能物流搬运机器人**，参加广东省大学生工程训练综合能力竞赛。比赛要求小车在无人遥控的情况下，自主完成：

1. 扫描场地二维码 → 获取任务序列（如"132+312"）
2. 识别旋转置物盘上红/绿/蓝三色物块
3. 导航到色环区域，按任务要求精确放置物块
4. 完成多轮搬运 + 码垛堆叠
5. 返回终点

整个过程**全自动**，涉及十几个外设同时工作。

## 三、核心技术学习收获

### 3.1 CAN总线通信与多电机协同控制

**学到了什么：**

- 传统PWM控制6个电机需要24个GPIO+6块驱动板，而CAN总线只用**2根线**挂所有设备
- ZDT驱动器自带位置环/速度环，STM32只需发"去位置X、速度Y"
- `zdt_sync(0)` 同步启动机制——让多个电机同时开始运动，保证底盘走直线
- CAN扩展帧ID设计：`(地址 << 8) | 包序号`，每个电机有独立地址

**关键函数：**
```c
zdt_vel(addr, dir, vel, acc, sync)    // 速度模式
zdt_pos(addr, dir, vel, acc, clk, abs, sync)  // 位置模式
zdt_home_trigger(addr, mode, sync)    // 触发回零
```

### 3.2 麦克纳姆轮运动学解算

**学到了什么：**

- 麦克纳姆轮可以实现**全向移动**：前进、后退、左右平移、原地旋转，且可同时进行
- 核心公式（4个轮子的速度由3个输入量解算）：

```c
speed[前右] = +v_x + v_y - w
speed[前左] = -v_x + v_y + w
speed[后左] = -v_x + v_y - w
speed[后右] = +v_x + v_y + w
```

- `v_y`前进分量→4轮同向；`v_x`横移分量→对角轮抵消；`w`旋转分量→左右侧反向
- 毫米→脉冲换算系数需要实地标定：Y方向10.3脉冲/mm，X方向10.5脉冲/mm

### 3.3 PID闭环姿态控制

**学到了什么：**

- 项目用IMU的Yaw角做反馈，构成**角度环**闭环控制
- PID三项的物理意义：
  - **P（比例）**：差多少补多少——"看到红灯就踩刹车"
  - **I（积分）**：累积误差慢慢补偿——"一直溜车就越来越用力"
  - **D（微分）**：变化快就减油门——"快到了提前松刹车防过冲"
- 角度环绕处理：从179°转到-179°，误差应该是-2°而不是358°（走近路）

```c
if (error > 180)  error -= 360;
if (error < -180) error += 360;
```

- 项目设计了**5组PID参数**应对不同场景：大角度转场用快速无积分，精确定位用带积分消残差

**调参口诀：**
> P不够到不了，P太多来回跳；
> D小了冲过头，D大了像蜗牛；
> I帮你消残差，太大就会震荡它。

### 3.4 IMU姿态传感

**学到了什么：**

- 维特智能IMU是成品模块，内部已集成MPU6050+单片机+卡尔曼滤波，直接串口输出Roll/Pitch/Yaw
- 不需要自己写姿态解算代码——理解了"模块级集成"和"从零造轮子"的取舍
- 角速度积分得角度，但纯积分会漂移→卡尔曼滤波融合加速度计（长期准）和陀螺仪（短期准）
- IMU数据每50ms读取一次，Yaw角直接作为PID的反馈量

### 3.5 串口通信协议设计（状态机）

**学到了什么：**

- 自定义帧协议：`0xFF`帧头 + 9字节ASCII载荷 + `0xFE`帧尾
- 用**三级状态机**实现收包：等帧头→收载荷→等帧尾，抗干扰能力强

```
State 0: 等0xFF → State 1
State 1: 收9字节 → State 2
State 2: 等0xFE → 置位标志，回到State 0
```

- 上下位机分工明确：STM32发单字节命令（'1'扫码、'7'粗定位、'8'精定位），上位机返回9字节坐标+颜色
- 13条视觉命令覆盖整个比赛流程的视觉需求

### 3.6 机器视觉（OpenCV）

**学到了什么：**

- **二维码识别**：pyzbar优先，降级到OpenCV QRCodeDetector，连续3次相同才确认
- **物块检测**：霍夫圆检测（HoughCircles）+ HSV颜色空间判断
  - HSV中红色跨0°需要双阈值处理
  - 绿色易受光照影响，需要更强的形态学膨胀
- **色环定位**：两阶段策略——粗定位（640×480快速找大致位置）→ 精定位（1920×1080精确对准）
- **稳定性验证**：位置连续30帧位移<10px才确认，颜色15帧中占比>70%才确认
- **排除法逻辑**：置物盘3个工位，检测2个颜色就能推算第3个：`A3 = {1,2,3} - {A1,A2}`

### 3.7 视觉引导与坐标映射

**学到了什么：**

- 摄像头像素坐标→世界物理坐标的转换，需要**比例尺标定**
- 比例尺不是常数，随距离非线性变化：`bilichi = -0.0035×(distance+80) + 1.1967`
- 粗定位和精定位用不同的比例因子（1.18 vs 0.29）
- 视觉引导的闭环：STM32发命令→上位机拍照识别→返回坐标→STM32移动→再确认→直到对准

### 3.8 传感器less碰撞回零

**学到了什么：**

- 升降电机**没有装限位开关**，靠电机驱动器的电流检测判断是否撞到机械限位
- 原理：撞限位→电机转不动→电流飙升→检测到电流>阈值并持续>时间→判定到位
- 这是工业上常见的**无传感器回零方案**，省硬件但参数要调好（电流750mA，时间30ms）

## 五、问题分析与解决思维

### 5.1 升降电机位置偏差问题——开环vs闭环的深刻理解

**问题：** 升降电机使用中位置越偏越大，最后抓不到物块。

**根因分析过程：**
1. 观察到刚回零时位置准确，使用越久偏差越大
2. 追踪代码发现 `shengjiang_control()` 下发脉冲后直接 `current_pos1 = target`，**不验证实际位置**
3. 每次运动可能丢步→软件位置被错误值覆盖→下一次基于错误位置计算→偏差累积
4. 还发现 `move_all()` 里硬编码覆盖了调用者传入的加速度参数（accel1=240），导致加速度实际上不可调

**解决方案（由简到难）：**
- 方案A：降低加速度（240→120），减少丢步
- 方案B：关键阶段前增加HOMEZERO回零
- 方案C：位置闭环——每次运动后通过CAN读取驱动器真实位置，用真实值更新软件位置
- 方案D：定期强制清零
- 方案F：检查机械问题（丝杆润滑、联轴器、供电）

**学到的思维：**
- 遇到累积性问题，首先怀疑**开环控制**——没有反馈就没有真相
- 排查问题要追踪到代码最底层，不能只看接口层
- 硬编码覆盖参数是隐蔽的bug来源，代码审查要注意
- 解决方案要有梯度，先试最简单的，再动根本性改造

### 5.2 系统鲁棒性设计

**学到了什么：**

- 每个视觉命令都有**超时保护**（10s~30s），超时后自动停机+LED报警
- 视觉检测失败（返回MISS）时**自动循环重试**，不是直接放弃
- 通信中断触发STM32超时锁定，不会一直傻等
- 加热仅在抓取/放置时开启，转移时关闭——节能且安全
- 舵机软启动（增量步进移动），避免突变抖舵

### 5.3 分层故障排查方法

**学到了什么：**

- 通信不通：先查物理层（接线/波特率）→ 再查协议层（帧格式）→ 最后查应用层（命令处理）
- 电机不动：查CAN终端电阻→查电机地址→查供电→逐个电机测试
- 视觉失败：查摄像头连接→查光照→查颜色阈值→查对焦→用预览模式观察
- 底盘走不直：查麦克纳姆轮安装方向→查脉冲系数→查电机一致性
