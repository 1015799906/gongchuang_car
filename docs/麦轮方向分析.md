# 麦轮方向分析（修正版）

## 一、出厂布局 vs 当前布局

### 出厂布局（代码匹配）

```
      前
电机2(右旋)    电机1(右旋)
        ┌────┐
        │ 车 │
        └────┘
电机4(左旋)    电机3(左旋)
      后
```

前两个右旋、后两个左旋。`wheel_forward_dir`：`{1,2}=0, {3,4}=1`——按前后分组，前轮同型、后轮同型。公式和方向表都成立。

### 当前布局（电机2和电机4互换后）

```
      前
电机2(左旋)    电机1(右旋)
        ┌────┐
        │ 车 │
        └────┘
电机4(右旋)    电机3(左旋)
      后
```

右侧(1,4)=右旋，左侧(2,3)=左旋。`wheel_forward_dir` 还是按旧布局的 `{1,2}=0, {3,4}=1`，电机2从右旋变左旋但 dir 没变，电机4从左旋变右旋但 dir 也没变。

## 三、代码现在实际做了什么

### 当前 `move_vel` 公式 + 调度

```
公式 speed[x]       发给    物理位置   轮型   当前dir
─────────────────────────────────────────────────
speed[1]=+vx+vy-w  电机2   前左      左旋    0
speed[2]=-vx+vy+w  电机1   前右      右旋    0
speed[3]=-vx+vy-w  电机3   后左      左旋    1
speed[4]=+vx+vy+w  电机4   后右      右旋    1
```

### `wheel_forward_dir` 当前值

```
电机1(右旋) dir=0     电机2(左旋) dir=0 ← 错误！同向实际正反转
电机3(左旋) dir=1     电机4(右旋) dir=1 ← 错误！同向实际正反转
```

右旋轮和左旋轮辊子相反——同一个 dir 值，一类轮前进时另一类必然倒退。电机2(左旋)被设成 dir=0，电机4(右旋)被设成 dir=1，四个轮子的正转方向全乱。

### 为什么 vy 没受影响

vy 在四个公式里都是 `+vy`——四条公式的符号同正同负。即使 dir 数组错了，只要四个轮子的正转指向一致（同向也行、反向也行，反正是同一步调），前进/后退就不显错。但一旦 vx/w 打破了这个"同向"假象，真正的问题就暴露了。

## 四、正确应该是什么

核心原则：**右旋轮统一用 dir=0，左旋轮统一用 dir=1。**

```
右侧 = 电机1(右旋) + 电机4(右旋)
左侧 = 电机2(左旋) + 电机3(左旋)
```

### 右旋轮（1,4）：统一 dir=0，公式 `+vx+vy-w`

- 前进：vy>0 → 正转 ✓
- 右移：vx>0 → 正转 ✓
- 顺时针：w>0 → -w，反转 ✓

### 左旋轮（2,3）：统一 dir=1，公式 `-vx+vy+w`

- 前进：vy>0 → 正转 ✓
- 右移：vx>0 → -vx，反转 ✓
- 顺时针：w>0 → +w，正转 ✓

## 五、修复方案

### 第1处：`wheel_forward_dir` — `motor_ack_test.c` 第 364 行

```c
// 改前:
static uint8_t wheel_forward_dir(uint8_t id) {
  switch (id) {
    case 1U: case 2U: return 0U;
    case 3U: case 4U: return 1U;
    default: return 0U;
  }
}

// 改后: 右旋→0, 左旋→1
static uint8_t wheel_forward_dir(uint8_t id) {
  switch (id) {
    case 1U: case 4U: return 0U;   // 右旋轮
    case 2U: case 3U: return 1U;   // 左旋轮
    default: return 0U;
  }
}
```

### 第2处：`move_vel` — `motor_ack_test.c` 第 396～413 行

```c
// 改前:
speed[1] = +vx + vy - w;
speed[2] = -vx + vy + w;
speed[3] = -vx + vy - w;
speed[4] = +vx + vy + w;

wheel_vel(2U, speed[1]);   // 发给电机2（旧：前左公式发前左）
wheel_vel(1U, speed[2]);   // 发给电机1（旧：前右公式发前右 — 实为交叉）
wheel_vel(3U, speed[3]);   // 发给电机3
wheel_vel(4U, speed[4]);   // 发给电机4

// 改后:
// 右旋侧（电机1,4）→ +vx+vy-w
// 左旋侧（电机2,3）→ -vx+vy+w

speed[1] = +vx + vy - w;   // 电机1(右旋) — 右旋侧公式
speed[2] = -vx + vy + w;   // 电机2(左旋) — 左旋侧公式
speed[3] = -vx + vy + w;   // 电机3(左旋) — 左旋侧公式（固定字修正: -w → +w）
speed[4] = +vx + vy - w;   // 电机4(右旋) — 右旋侧公式（固定字修正: +w → -w）

wheel_vel(1U, speed[1]);   // 发给电机1（前右,右旋）
wheel_vel(2U, speed[2]);   // 发给电机2（前左,左旋）
wheel_vel(3U, speed[3]);   // 发给电机3（后左,左旋）
wheel_vel(4U, speed[4]);   // 发给电机4（后右,右旋）
```

## 七、不影响主固件

`race_chassis.c` 的 `car_move()` 没有用 `wheel_forward_dir`，而是直接写死在 `zdt_vel` 的 dir 参数中——它内置的就是 `{1,4}` 和 `{2,3}` 的分组，已经正确。问题只影响 `motor_ack_test.c` 的 `MOVE`/`LLM` 等调试命令。
