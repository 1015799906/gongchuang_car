# 升降电机位置偏差问题分析与解决方案

---

## 一、问题现象

- 上电初始化时，升降电机执行 HOMEZERO（碰撞回零到顶部），此时位置准确
- 后续正常使用过程中，升降电机出现**位置累积偏差**
- 具体表现为：命令它降到 60mm 位置，实际位置可能是 58mm 或 62mm
- 使用时间越长、动作次数越多，偏差越大
- 偏差积累到一定程度后，物块放不准、抓不到，甚至可能撞机械限位

---

## 二、根因分析

### 2.1 核心原因：开环控制 + 软件位置信任

升降电机（ZDT 步进电机，CAN 地址 5）的当前控制方式是**完全开环**的：

```
上位逻辑（STM32）                           下位硬件（ZDT驱动器+步进电机）
─────────────────                           ──────────────────────────────
"我让你走 60mm"  ──── CAN脉冲指令 ───→     收到脉冲 → 步进电机转动
current_pos1 = 60  ← 直接赋值（信任）       实际到了哪里？→ 无人检查
```

关键代码在 `race_chassis.c` 第 992-993 行：

```c
// shengjiang_control() 函数
time = shengjiang_move_delay((float)pulses, accel, speed);
current_pos1 = (float)target_pos;   // ← 直接设为目标值，不验证
return time;
```

`current_pos1`（软件记录的当前位置）在下发脉冲指令后**立即被设为目标值**，完全不管电机是否真的走到了。如果电机因为任何原因少走了几步（丢步），这个偏差就会被永久记录进 `current_pos1`，后续所有移动都会基于这个错误位置计算。

### 2.2 偏差如何一步步累积

```
假设电机因为负载大，每次 60mm 行程丢 2mm：

动作序列               软件认为位置      实际物理位置      偏差
────────────────────────────────────────────────────────────────────
HOMEZERO 回零           current_pos1=0   实际=0            0mm
shengjiang_control(60)  current_pos1=60  实际=58          -2mm
shengjiang_control(10)  current_pos1=10  实际=8           -2mm  (偏差传递)
shengjiang_control(60)  current_pos1=60  实际=56          -4mm  (偏差累积!)
shengjiang_control(10)  current_pos1=10  实际=6           -4mm
shengjiang_control(60)  current_pos1=60  实际=54          -6mm  (越积越大!)
...
最后 shengjiang_control(0) → 实际到了 -6mm，已经撞到上限位了
```

偏差链条：每次运动都可能引入少量丢步 → `current_pos1` 被错误值覆盖 → 下一次运动的脉冲数是基于错误的 `current_pos1` 算出来的 → 偏差只会越来越大。

### 2.3 为什么回零时没问题，后续就不行了

回零用的是传感器less碰撞检测（`zdt_home_trigger(mode=2)`），电机一直转到机械限位碰停，**驱动器自己判断到位**——这是一个闭环过程。

回零完成后：
```c
zdt_clear_pos(SHENGJIANG_ADDR);   // 清驱动器内部计数器
current_pos1 = 0.0f;              // 清软件位置
```

此时软件位置和物理位置是同步的，所以刚回零时是准的。

但之后的 `shengjiang_control()` 走的是普通位置模式（`zdt_pos`），驱动器的位置计数器虽然在转，但 **STM32 端从来不读它**，全靠自己的 `current_pos1` 变量跟踪。一旦这个软件变量跟驱动器的实际计数器脱节，就再也回不去了。

### 2.4 造成丢步的具体原因

| 原因 | 说明 | 影响程度 |
|------|------|----------|
| **加速度过大** | `move_all()` 中硬编码 `accel1=240`，加速度太陡，步进电机在高负载下更容易丢步 | ★★★★★ |
| **升降负载重** | 机械结构（丝杆、导轨、夹爪+物块重量）增加了电机扭矩需求 | ★★★★ |
| **无位置回读** | 代码从不用 `zdt_read(SHENGJIANG_ADDR, ZDT_S_CPOS)` 读取驱动器的真实脉冲位置来校准 | ★★★★★ |
| **相对移动模式** | `zdt_pos(..., false, false)` — `abs=false` 相对模式，`sync=false` 不同步 | ★★★ |
| **运动时间估算不准** | `shengjiang_move_delay()` 用梯形速度曲线估算时间，实际运动时间可能不匹配 | ★★★ |
| **HOMEZERO 只执行一次** | 比赛 9 个阶段跑下来，升降要动几十次，但只在阶段2调用了一次 `race_shengjiang_homezero()` | ★★★★★ |
| **机械磨损/润滑变化** | 长期使用后机械阻力变大，相同电流下更容易丢步 | ★★ |

### 2.5 move_all() 里还有一个隐藏问题

`race_chassis.c` 第 1162-1163 行：

```c
int move_all(float target_pos, uint16_t speed, uint8_t accel,
             float target_pos1, uint16_t speed1, uint8_t accel1,
             float target, float speed_of_yuntai)
{
    accel = 230U;       // ← 把调用者传进来的 accel 覆盖了！
    accel1 = 240U;      // ← 把调用者传进来的 accel1 覆盖了！
    speed1 = 2000U;     // ← 把调用者传进来的 speed1 覆盖了！
    ...
    time2 = shengjiang_control((int)target_pos1, speed1, accel1);
}
```

这意味着无论你在 `race_task.c` 里把 `ACT_LIFT_ACC` 设成多少，`move_all()` 实际传给升降电机的是**硬编码的 240**。而 `race_task.c` 里的 `act_pose()` 和大部分动作原语都走 `move_all()`，所以加速度参数实际上是不可调的。

## 三、验证方法

### 3.1 确认是否存在偏差

烧录 motor_test 固件，用以下流程测试：

```
# 第1步：回零
SJ HOMEZERO
SJ READ             ← 记录此时的实际脉冲位置，应为 0

# 第2步：反复升降
SJ 60 600 80        ← 降到 60mm
SJ 0 600 80         ← 升回 0mm
SJ 60 600 80
SJ 0 600 80
SJ 60 600 80
SJ 0 600 80
# (重复 10 次)

# 第3步：回到 "0" 后，检查实际位置
SJ READ             ← 驱动器的实际脉冲位置是多少？
                    ← 如果是 0，说明没有偏差
                    ← 如果不是 0，偏差 = 实际脉冲数 / 80
```

### 3.2 测量丢步量

每次满行程（0→60→0）后，记录驱动器实际脉冲位置：

| 次数 | 实际脉冲位置 | 换算偏差(mm) |
|------|-------------|-------------|
| 1 次往返后 | | |
| 5 次往返后 | | |
| 10 次往返后 | | |
| 20 次往返后 | | |

如果 10 次之后偏差超过 1mm (=80脉冲)，就说明有明显的累积丢步。

## 四、解决方案（由简到难）

### 方案 A：降低加速度（最简单，立即见效）

把 `race_chassis.c` 第 1162 行的硬编码加速度改小：

```
当前: accel1 = 240U;
改为: accel1 = 120U;  (或更低，如 80)
```

降低加速度可以让电机起步更平稳，大大减少丢步。
- 代价：运动速度变慢
- 效果：通常立竿见影

### 方案 B：每次动作前重新回零（中等改动）

在比赛流程的关键节点增加 HOMEZERO 调用。当前只有阶段2（`race_stage_prepare_actuators`）调用了一次 `race_shengjiang_homezero()`。

在 `race_task.c` 中，在每个需要精确定位的阶段前加一句：

```c
// 例如在 race_stage_first_ring_task012() 开头加：
(void)race_shengjiang_homezero();

// 在 race_stage_third_ring_task345() 开头加：
(void)race_shengjiang_homezero();
```

- 优点：每次用之前都是准确的
- 缺点：回零操作本身耗时 3~10 秒，会增加总比赛时间
- 注意：回零只能在安全位置（顶部没障碍物）时执行

### 方案 C：位置闭环——读取驱动器真实位置（推荐，根本性解决）

当前代码从不读取驱动器的真实脉冲位置。在 `shengjiang_control()` 中增加一步验证：

**改前（当前代码）：**
```c
// 发送脉冲后
current_pos1 = (float)target_pos;   // 盲目信任
```

**改后思路：**
```c
// 发送脉冲后，等待运动完成
// 然后通过 CAN 读取驱动器的真实当前位置
zdt_read(SHENGJIANG_ADDR, ZDT_S_CPOS);
// 把读回的真实脉冲数转换成 mm
// 用真实值覆盖 current_pos1
// 这样每次移动后软件位置和物理位置是同步的
```

- 优点：从根本上消除累积偏差
- 缺点：需要改动代码逻辑，增加约 20ms 的 CAN 读取时间

### 方案 D：定期强制清零（治标方案）

在动作链中每隔几次动作后，让升降回一次零。比如在 `act_safe_transfer()` 之后增加判断：

```
if (运动次数 % 5 == 0) {
    race_shengjiang_homezero();
}
```

### 方案 E：调整回零碰撞检测参数

如果 HOMEZERO 本身也有偏差（每次回零后位置不一样），需要调整碰撞检测参数：

```
# motor_test 固件测试：
SJ HCFG 1 600 40     ← 降低电流到 600mA，缩短时间到 40ms（更敏感）
SJ HOMEZERO
SJ READ              ← 确认位置=0

# 再次升降后回零，验证一致性：
SJ 60 600 80
SJ HOMEZERO
SJ READ              ← 应该还是 0
```

### 方案 F：检查机械问题

如果上述方案都试过还是偏差大，可能不是软件问题：

- 升降丝杆是否润滑不足
- 导轨是否有异物/毛刺
- 电机联轴器是否松动
- 负载是否超出电机额定扭矩
- 检查 24V 供电是否稳定（电压跌落会导致扭矩不足）

## 五、推荐的实施顺序

```
第1步：先做方案A
  → 把 move_all() 里的 accel1 从 240 降到 120
  → 重新烧录 motor_test，跑 3.1 的测试
  → 如果偏差明显减小（<1mm/10次），说明问题主要在加速度

第2步：如果方案A不够，加方案B
  → 在 race_task.c 的关键阶段前加 HOMEZERO
  → 测量总比赛时间，确保不超时

第3步：如果还不行，实施方案C
  → 在 shengjiang_control() 中增加驱动器位置回读

第4步：做一次方案F的机械检查
  → 排除硬件原因

第5步：微调方案E
  → 确保 HOMEZERO 本身的一致性
```
