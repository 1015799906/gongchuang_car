# 第一部分：项目总体分析

## 1. 项目目标

**用一句话说：** 让一台四轮小车自动识别彩色物块，按比赛任务要求搬运到指定位置。

**用一段话说：** 比赛主办方在场地里放了一个二维码（告诉你任务是什么）、一个旋转置物盘（上面有三个红/绿/蓝色物块）、四个色环区域。小车要自己扫码获取任务序列，自己识别物块颜色，自己导航到色环位置，用机械臂抓取物块并放到正确的环上。整个过程**全自动**，没有人遥控。

**跟你在学校做的区别：**
- 学校里：点亮一个 LED、驱动一个舵机、串口打印 "Hello World"
- 这个项目：十几个外设同时工作，CAN 总线上挂了 6 个电机，两个摄像头做实时视觉，树莓派和 STM32 实时通信协同

# 第四部分：重点代码解析

## 4.1 电机驱动（CAN + ZDT协议）

### 原理

这个项目没有用你熟悉的 TB6612 + PWM 方式。而是用 **CAN 总线 + ZDT 智能步进驱动器**：

```
STM32 ──CAN总线(两根线)──→ ZDT驱动器1(地址1, 前右轮)
                   ├──→ ZDT驱动器2(地址2, 前左轮)
                   ├──→ ZDT驱动器3(地址3, 后左轮)
                   ├──→ ZDT驱动器4(地址4, 后右轮)
                   ├──→ ZDT驱动器5(地址5, 升降)
                   └──→ ZDT驱动器6(地址6, 平推)
```

**为什么不直接用 PWM？**
- 6 个电机，用 PWM 需要 24 个 GPIO + 6 个驱动板
- CAN 总线只需要 2 根线（CAN_H + CAN_L），挂多少设备都行
- ZDT 驱动器自带位置环、速度环、回零功能，STM32 只发"去位置 X、速度 Y"就行

### CAN 帧格式（以 `zdt_pos` 为例）

```
扩展帧ID: (地址 << 8) | 包序号
数据: [功能码] [方向] [速度高] [速度低] [加速度] [脉冲0] [脉冲1] [0x6B]
                                                              ↑
                                                        所有ZDT命令以此结尾
```

例：让地址5(升降)向下走10000脉冲，速度600，加速度80
```
ID: 0x00000500 (地址5, 包0)
数据: FD 00 02 58 50 00 00 27 10 00 00 6B
      ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑  ↑
      功 方 速度 加速度      脉冲数      尾字节
      能 向 600   80       10000
      码
```

### 关键函数

```c
zdt_vel(addr, dir, vel, acc, sync)    // 速度模式: "以速度vel转"
zdt_pos(addr, dir, vel, acc, clk, abs, sync)  // 位置模式: "走clk个脉冲"
zdt_stop(addr, sync)                  // 急停
zdt_sync(0)                           // 同步启动(让之前缓冲的指令同时开始)
zdt_home_trigger(addr, mode, sync)    // 触发回零
```

## 4.2 麦克纳姆轮运动解算

### 为什么要用麦克纳姆轮

普通轮子只能前进后退+差速转弯。麦克纳姆轮可以**全向移动**——前进、后退、左右平移、原地旋转，同时进行。

### 核心公式（`car_move` 函数）

```c
// 输入：期望的 X速度、Y速度、旋转角速度
// 输出：4个轮子各自的速度

speed[1] = +v_x + v_y - w;   // 前右轮
speed[2] = -v_x + v_y + w;   // 前左轮
speed[3] = -v_x + v_y - w;   // 后左轮
speed[4] = +v_x + v_y + w;   // 后右轮
```

**怎么理解：**
- `v_y` 是前进分量，4个轮子都加 → 前进时4轮同向转
- `v_x` 是横移分量，对角轮抵消 → 左移时前右+后左正转，前左+后右反转
- `w` 是旋转分量 → 逆时针旋转时右侧两轮向前，左侧两轮向后

## 4.3 PID 姿态控制

### 为什么需要 PID

小车在场上导航时，IMU 给出当前朝向(Yaw角)。目标是让小车朝向某个角度（比如 90°）。PID 计算"差了多少，该用多大劲儿转"。

### 三种"环"

这个项目只用到了**角度环**（也称为位置环），没有速度环：

```
目标角度(90°) ──→ [PID] ──→ 输出=角速度w ──→ 底盘执行 ──→ IMU反馈当前角度 ──→ 回到PID
                                         ↑                              │
                                         └──────────────────────────────┘
```

### 代码实现（`PID_Calc` 函数）

```c
void PID_Calc(PID *pid, float reference, float feedback)
{
    // P: 比例项 —— "差多少，补多少"
    pout = error * pid->kp;

    // D: 微分项 —— "变化快，减油门"（防过冲）
    dout = (error - lastError) * pid->kd;

    // I: 积分项 —— "一直差，慢慢加"（消除稳态误差）
    integral += error * pid->ki;

    // 输出 = P + I + D，限幅防止失控
    pid->output = pout + dout + integral;
}
```

### 角度环绕处理（-180°/180° 跳变）

```c
// 如果从 179° 转到 -179°，差不应该是 358°，而应该是 -2°
if (error > 180)  error -= 360;   // "走近路"
if (error < -180) error += 360;
```

### 5 组 PID 参数

不同场景用不同力度：

| Profile | 场景 | kp | ki | kd | 特点 |
|---------|------|----|----|-----|------|
| 0 | 大角度转场(0→90°) | 2.0 | 0 | 0.8 | 快速，不积分 |
| 1 | 低功率模式 | 3.3 | 0 | 1.8 | 输出限30，防止太猛 |
| 3 | 稳态微调 | 2.0 | 0.05 | 0.4 | 带小积分，消除残留误差 |
| 4 | 精确定位 | 2.0 | 0.07 | 0.4 | 带大积分 |

### 如何调 PID（口诀）

```
"P 不够到不了，P 太多来回跳；
 D 小了冲过头，D 大了像蜗牛；
 I 帮你消残差，太大就会震荡它。"

调法: 先把 I 和 D 设为 0
  → 调 P 到稍微过冲一点
  → 加 D 消除过冲
  → 如果有残留误差，加一点 I
```

## 4.4 编码器

这个项目用的 ZDT 步进电机**自带编码器**（在驱动器内部闭环），STM32 不直接接编码器。所以：

- **位置：** 通过 CAN 发送位置脉冲指令(`zdt_pos`)，驱动器自己保证到达目标脉冲数
- **速度：** 通过 CAN 发送速度指令(`zdt_vel`)，驱动器自己闭环稳速
- **校验：** 通过 `zdt_read(addr, ZDT_S_CPOS)` 读回实际脉冲数

**跟学校实验的区别：** 学校可能用光耦编码器接 TIM 编码器模式，手动计脉冲。这里驱动器替你做了，你只需要 CAN 发指令。

## 4.5 IMU（MPU6050 的升级版）

### 为什么不是 MPU6050

维特智能 IMU 是成品模块，里面已经集成了 MPU6050 芯片 + 单片机 + 姿态解算算法（卡尔曼滤波/互补滤波），直接串口输出 Roll/Pitch/Yaw 角度。**不需要你自己写姿态解算代码。**

### 代码流程

```
上电 → imu_init()
  → WitInit(NORMAL模式, 地址0x50)
  → 注册回调: SensorDataUpdata(收到角度时更新标志位)
  → 启动USART2接收中断

每50ms → imu_scan(fAcc, fGyro, fAngle)
  → 检查是否有新角度数据
  → sReg[Yaw] / 32768 × 180° = Yaw角
  → 这个 Yaw 直接给 PID 做反馈
```

### 加速度、角速度、角度是什么关系

```
加速度 → 积分一次 → 速度 → 积分一次 → 位置
角速度 → 积分一次 → 角度

但纯积分会累积误差（漂移），所以 IMU 内部用卡尔曼滤波
融合加速度计（长期准确但短期噪声大）和陀螺仪（短期准确但长期漂移）
```

## 4.6 通信：上位机 ↔ STM32 协议

### 物理层

USART1, 115200, 8N1。两根线（PA9 TX, PA10 RX）。

### 上位机 → STM32（11字节帧）

```
| 0xFF | 9字节ASCII载荷 | 0xFE |
  ↑                       ↑
 帧头                     帧尾

例: 握手 "987654321" → 0xFF 39 38 37 36 35 34 33 32 31 0xFE
   坐标 "095505191" → 0xFF 30 39 35 35 30 35 31 39 31 0xFE
                     → x=0955, y=0519, color=1(红)
```

### STM32 → 上位机（单字节）

只发一个字符，上位机的 Python 用 `readline()` + 0.1秒超时接收。不需要结尾的 `\n`。

### STM32 侧状态机（`host_on_rx_byte`）

```
State 0: 等 0xFF → 收到后进入 State 1
State 1: 收 9 字节负载 → 收满 9 字节进入 State 2
State 2: 等 0xFE → 收到后置位 s_rx_flag，回到 State 0
```

### 13 条视觉命令

| 命令 | 含义 |
|------|------|
| '1' | 扫二维码 |
| '2' | 定位第一个物块 |
| '3' | 识别转盘颜色编码 |
| '4' | 第二圈颜色编码 |
| '5','6','b','c' | 验证物块颜色 |
| '7' | 色环粗定位 |
| '8' | 色环精定位 |
| '9' | 码垛定位 |
| '0' | 码垛精定位 |
| 'a' | 第二圈初始检测 |
| 'd' | 直线纠偏 |

### 上位机（Python）

```python
# 发送
def send_data(data):
    payload = str(data)[:9].ljust(9, b"\x00")  # 补齐9字节
    ser.write(bytes([0xFF]) + payload + bytes([0xFE]))

# 接收
def receive_data():
    return ser.readline().decode("utf-8").strip()  # 读单字节
```

# 第五部分：项目核心算法

## 真正体现技术含量的 5 个点

### 1. 多传感器融合的视觉引导定位

这是项目的灵魂。流程：
```
1. 摄像头拍照 → 霍夫圆检测找到物块 → HSV颜色空间判断颜色
2. 图像坐标(px) → 带比例尺修正 → 世界坐标(mm) → 发给STM32
3. STM32 根据世界坐标移动底盘到位
4. 如果颜色为 MISS → 自动重试
```

**创新点：** "粗定位+精定位"两阶段策略——先用低分辨率快速找到大致位置，靠近后再用高分辨率精确对准。

### 2. CAN 总线多电机协同控制

6 个电机挂一条 CAN 总线上，每个有独立地址。`zdt_sync(0)` 可以让多个电机**同时启动**，实现多轴联动。底盘 4 轮的位置移动需要严格同步，否则走不直。

### 3. 碰撞检测回零（传感器less HOMEZERO）

升降电机**没有装限位开关**，靠电机驱动器的电流检测来判断是否撞到机械限位：
```
撞限位 → 电机转不动 → 电流飙升 → 驱动器检测到电流>阈值并持续>时间 → 判定到位
```
这是工业上常见的无传感器回零方案。

### 4. 状态机驱动的比赛任务编排

整个比赛被拆成 9 个阶段函数，每个阶段内部又有若干子步骤。出错时通过超时机制自动停机（`race_host_timeout_stop`），不会一直傻等。

### 5. 转盘颜色编码的"排除法"逻辑

置物盘有 3 个工位，3 个不同颜色的物块。通过检测其中 2 个的颜色，推算第 3 个的颜色：
```python
A3 = {1,2,3} - {A1, A2}  # 排除法
```
并判断旋转方向（顺时针/逆时针），计算每个物块对应去哪个环。

### 如果参加比赛，可以提升的点

- **视觉升级：** 用 YOLO/目标检测替代霍夫圆+HSV，光照鲁棒性更好
- **定位升级：** 加入 UWB 室内定位或二维码地标辅助全局定位
- **路径规划：** 加入 A* 或 Dijkstra 做最优路径，而不是写死的固定路线
- **闭环控制：** 升降/平推电机加上 CAN 回读位置做位置闭环

# 第七部分：面试与答辩准备

## 项目介绍（1分钟版本）

> 我参与的是一个智能物流搬运竞赛机器人项目。我负责 STM32 下位机固件的开发和调试。机器人通过 CAN 总线控制 6 个步进电机实现全向移动和物料搬运，配合 IMU 做 PID 姿态闭环，通过串口协议与上位机视觉系统协同，实现从二维码识别、物块定位抓取、色环精确放置的全自动竞赛流程。我在项目中主要做了底盘运动控制的参数标定、升降电机回零逻辑的调试优化，以及调车固件的串口命令系统维护。

## 技术难点

1. **CAN 总线多电机同步控制：** 6 个电机需要精确的时间同步才能保证底盘直行不偏、多轴联动不碰撞
2. **传感器less碰撞回零：** 没有限位开关，靠电流检测判定机械零位，参数调不好要么提前停要么撞坏
3. **视觉-运动坐标映射：** 摄像头像素坐标到世界物理坐标的转换，需要精确标定比例尺和偏移量
4. **全自动流程的鲁棒性：** 每个环节都可能失败（视觉误检、通信超时、机械偏差），需要完善的超时保护和重试机制

## 常见答辩问题

**Q：为什么用 CAN 总线而不是直接用 PWM？**
A：6 个电机用 PWM 需要大量 GPIO 和驱动板，CAN 两线挂所有设备，拓扑简单，而且 ZDT 驱动器自带闭环，减少 STM32 的计算负担。

**Q：升降电机的 0 点怎么确定的？**
A：用传感器less碰撞回零——电机向上运动到机械限位，撞停后电流飙升，驱动器检测到电流超阈值后自动停止并清零位置。

**Q：PID 参数怎么调的？**
A：先 I/D=0，调 P 到稍有超调，然后加 D 消除过冲，最后视情况加微量 I 消除稳态误差。比赛中有5组参数应对不同场景。

**Q：如果视觉检测失败了怎么办？**
A：上位机返回 "4"(MISS)，STM32 自动循环重试，每轮有超时保护。如果最终仍失败，整个比赛流程会超时停机，LED 快闪报警。

**Q：你在这个项目中最大的贡献是什么？**
A：（根据你实际做的工作回答）比如：重新标定了所有执行器的位置参数、修复了升降电机回零方向错误的问题、搭建了 VS Code + Cortex-Debug 开发环境替代原来的 STM32CubeIDE 等。

# 第八部分：术语解释词典

## PID（比例-积分-微分控制）

**用开车比喻：** 你要开车到一个红绿灯前停下。
- **P（比例）：** 看到红灯就踩刹车，离得越近踩得越重——"跟差距成正比"
- **I（积分）：** 如果踩了半天车还在往前溜，你就越来越用力——"累积误差，慢慢补偿"
- **D（微分）：** 如果车速很快地接近停止线，你会提前松一点刹车防止点头——"变化太快，收敛一点"

## PWM（脉宽调制）

**用水龙头比喻：** 你不能让水龙头只"开"或"关"，你想要 50% 水流。PWM 就是快速开关水龙头——开1秒关1秒循环，平均下来就是 50%。开关够快（比如每秒1000次），舵机/电机感受到的就是平滑的"一半功率"。

## CAN 总线

**用教室讨论比喻：** 老师在黑板上写消息，加个前缀"给张三的"，教室里所有人都看到了，但只有张三会处理。CAN 总线上每个设备都在"听"，但只处理发给自己的消息(地址匹配)。不需要点对点连线，两根线搞定所有设备。

## DMA（直接存储器访问）

**用快递比喻：** 没有 DMA：你要亲自把每个快递从 A 点搬到 B 点（CPU 自己搬运每个字节）。有了 DMA：你告诉快递员"把这堆东西搬到那里去"，然后你可以做别的事（CPU 去处理其他任务，DMA 后台搬运数据）。

## 编码器

**用计步器比喻：** 电机轴转一圈，编码器输出 N 个脉冲。数脉冲就知道转了多少圈、转了多少角度。配合时间信息（每秒多少脉冲），就能算出速度。

## 卡尔曼滤波

**用信任投票比喻：** 你有两个信息源——陀螺仪说"我在转"（短期准但长期漂）、加速度计说"重力指向下方"（长期准但短期抖）。卡尔曼滤波不是简单取平均，而是根据各自的"可信度"动态加权融合，给出最优估计。

## 状态机

**用自动门比喻：** 自动门有三种状态——"关闭"→ 有人靠近 → "打开中"→ 完全打开 → "打开" → 人走了 → "关闭中"→ 完全关闭 → "关闭"。每个状态下，系统只做该状态下的事，收到特定信号才转换状态。这个项目里 `host_proto.c` 的收包逻辑就是一个三级状态机：等帧头→收载荷→等帧尾。

## RTOS（实时操作系统）

**用厨房比喻：** 裸机程序 = 一个人做菜，只能一步一步来，炒菜时不能同时切菜。RTOS = 多个人同时干活，任务调度器分配时间片，CPU 在任务间快速切换，看起来像"同时在跑"。这个项目目前是裸机，没有 RTOS。如果以后加了更复杂的任务（比如同时做视觉+运动+通信），可以考虑引入 FreeRTOS。

## 闭环 vs 开环

- **开环：** 你发"往前走100步"，电机就走100步，走到哪了你不检查。如果地面滑、丢步了，你以为到了其实没到。
- **闭环：** 你发"走到坐标X"，然后不断读取编码器/IMU的位置，和X比较，差多少补多少，直到真正到达。

这个项目里底盘有 IMU 反馈→PID→算是角度闭环。但升降和平推是开环的（发目标位置，直接设软件位置=目标），这也是之前升降偏差问题的根因。
