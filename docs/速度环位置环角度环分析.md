## 一、三个环各自是谁、在哪

```
┌─────────────────────────────────────────────────────┐
│                    STM32 软件层                       │
│                                                      │
│  ┌─────────────────┐    ┌─────────────────────┐     │
│  │  角度环 (LLM)    │    │  位置环(底盘开环)     │     │
│  │  IMU→PID→w      │    │  car_move_distance   │     │
│  │  你能调的PID ✓   │    │  无反馈 ×             │     │
│  └────────┬────────┘    └──────────┬──────────┘     │
│           │                        │                  │
│           └────────┬───────────────┘                  │
│                    ↓                                  │
│              move_vel() / car_move()                  │
│              麦克纳姆轮解算 → w 和 vx/vy 分到4轮       │
│                    ↓                                  │
└───────────────────┬─────────────────────────────────┘
                    │ CAN: zdt_vel() / zdt_pos()
                    ↓
┌─────────────────────────────────────────────────────┐
│              ZDT 电机驱动器（每轮一个）                 │
│                                                      │
│  ┌──────────────┐    ┌──────────────┐               │
│  │  速度环       │    │  位置环       │               │
│  │  编码器→PI   │    │  脉冲计数→P  │               │
│  │  厂固化的 ×   │    │  厂固化的 ×   │               │
│  └──────────────┘    └──────────────┘               │
│                                                      │
│  你不可调 —— 驱动器厂商写死的参数                       │
└─────────────────────────────────────────────────────┘
```

| 环 | 运行位置 | 反馈源 | 输出 | 你能调？ | 代码位置 |

| 底盘位置环 | STM32 | **无** | 位置脉冲 | ❌ 开环 | `race_chassis.c:641` |

## 二、角度环和底盘位置环的关系

角度环和底盘位置环在代码里是**独立叠加**的，不是级联关系：

```
目标 yaw → [角度环 PID] → w
目标 x,y → [走固定脉冲] → vx, vy
                            │
                  ┌─────────┘
                  ↓
     move_vel(vx, vy, w) 或 car_move(vx, vy, w)
                  │
       麦克纳姆轮解算（四个轮子的速度 = f(vx,vy,w)）
                  │
              zdt_vel() → CAN → 驱动器速度环
```

**关键点：vx/vy 和 w 是平级的、同时叠加的。** 不是位置环算出 vx/vy 再给角度环，也不是角度环算出 w 再给位置环。两个独立算，在 `move_vel` 里汇合。

比赛代码 `race_task.c` 里也是这样用的：
```c
PID_move(-30, 0, 0, 400, 0.0, LOW_OUTPUT);  // 角度环：转到0°
car_move1(0.0f, -530.0f, 150, 200);          // 开环位置：后退530mm
PID_move(0, 0, 0, 1000, 90.0, TRANSIT);      // 角度环：转到90°
car_move1(0.0f, -1700.0f, 150, 250);         // 开环位置：前进1700mm
```

**先转对方向，再走直线。** 这就是底盘位置环和角度环的关系——它们交替执行，不是同时级联。

## 四、速度环（ZDT驱动器内部，不可调）

你要调的"速度环"在 ZDT 驱动器内部，STM32 只管下发速度指令：

```
STM32: zdt_vel(addr, dir, speed, acc, sync)
         ↓ CAN
ZDT驱动器: 收到速度指令 → 内部速度环PI → 电流环 → 电机转
           反馈：编码器 → 内部速度环
```

你唯一能影响的是加速度 `ACC` 参数，代码在 `motor_ack_test.c:1344`：

```c
// ACC 160 → s_vel_acc = 160 → wheel_vel() → zdt_vel(..., s_vel_acc, ...)
static void handle_acc(char *params)    // 第1344行
```

加速度默认 160（`motor_ack_test.c:33`），范围 0~255。加速度越大，电机起步越猛，但丢步风险也大。

## 五、位置环分析

### 5.1 底盘位置控制——开环脉冲

```
car_move_distance_y(y) → 计算脉冲 = |y| × 10.3
  → zdt_pos(四个轮子, 脉冲, 同步)
  → car_move_delay() 估算时间 + 等待
  → 返回（假设走到了，不验证）
```

```c
// race_chassis.c:665
void car_move_distance_y(float y) {
    quanshu = (int)(|y| × 10.3);    // mm → 脉冲
    v_y = speed × (y的符号);
    四个轮: zdt_pos(id, dir, v, acc, quanshu, false, true);
    zdt_sync(0);                     // 同时启动
}

// race_chassis.c:689
double car_move_delay(distance, a, speed, dir) {
    梯形速度曲线时间估算：
    加速段: t_acc = 2000 × speed / a
    总时间: t = 1000 × (总脉冲-加速脉冲) / (320×speed/6) + t_acc
    delay_ms1(t);
}
```

**这是纯开环。** 实际走了多远没人管。地面滑、丢步 → 位置偏差累积。

### 5.2 升降位置控制——开环

```c
// race_chassis.c:965
double shengjiang_control(target, speed, accel) {
    pulses = |Δmm| × 80;            // mm → 脉冲
    zdt_pos(5, dir, speed, accel, pulses, false, false);
    current_pos1 = target;           // ← 软件位置直接设！不验证！
}
```

**软件位置和物理位置会脱节。** 这就是之前升降偏差问题的根因。

### 5.3 脉冲换算系数

## 六、三个环的关系总结图

```
比赛流程（race_task.c）:

阶段4: 色环放置
  PID_move(0,0,0, 1000, 90, TRANSIT)    ← 角度环: 转到90°
         ↓ 角度环闭环（IMU反馈）
  
  car_move1(0, 400, 150, 200)           ← 位置环: 前进400mm
         ↓ 开环脉冲（无反馈）
  
  PID_move(0,0,0, 1000, -180, TRANSIT)  ← 角度环: 转到-180°
         ↓ 角度环闭环

  car_move1(0, -1700, 150, 250)         ← 位置环: 后退1700mm
         ↓ 开环脉冲

  while(视觉没找到) {                     ← 视觉引导
    car_move_distance(direct_x, direct_y) ← 位置环: 小幅调整
  }

  PID_move(0,0,0, 1000, -180, KI_HIGH)  ← 角度环: 精对准
         ↓ 角度环闭环（带积分消除残差）
```

**规律：先转方向（角度环闭环），再走直线（位置环开环），最后精对准（角度环+积分）。**

## 七、调参方案

### 7.1 角度环（你可以调的）

当前状态分析（基于你 P=0.12 D=0.06 数据）：

- output 在 5~25 范围，maxOutput=25 限制了你
- 小角度（45°）也能震，说明 maxOutput=25 下 P=0.12 仍然偏大
- D=0.06 压不住 45° 时的冲量

**推荐策略：** 先修方向（加负号），然后

```
第1步: 纯P，小角度测试
  SET P:0.06 I:0 D:0
  LLM ON 0 30        ← 从30°开始，比45°更安全
  如果稳 → 逐步加到 P=0.08, P=0.10
  找到刚好不震的 P 值

第2步: 纯P，大角度测试
  LLM ON 0 90        ← 找到的 P 值下测大角度
  如果大角度偏慢 → 可以接受（maxOutput=25 限制的）
  如果大角度也稳 → P 值正确

第3步: 加 D
  如果到位后有轻微过冲：
  SET P:0.08 I:0 D:0.02
  LLM ON 0 90
  微调 D（每次 ±0.02）

第4步: 全方向验证
  LLM ON 0 -90      ← 反方向
  LLM ON 0 180      ← 大角度
  LLM ON 0 45       ← 任意角度

第5步: 记录
  STATUS → 记下 kp/ki/kd
```

### 7.2 速度环（你可以调的有限参数）

| 参数 | 命令 | 作用 | 默认 | 建议 |
|------|------|------|------|------|
| 加速度 | `ACC 160` | 电机起步力度 | 160 | 轮子打滑→降低；起步太慢→提高 |

提速/降速测试：
```
ACC 120
MOVE 0 100 0 3000          ← 前进看是否打滑
ACC 200
MOVE 0 100 0 3000          ← 看是否有提升
```

### 7.3 位置环（开环，调的系数）

底盘走不准：
```
# 前进100mm测试
PULSE F 1030 200 100       ← 100mm × 10.3

# 如果实际走了90mm: 新系数 = 10.3 × 100/90 = 11.44
# 如果实际走了110mm: 新系数 = 10.3 × 100/110 = 9.36

# 改 race_chassis.c:675 的 10.3
```

升降走不准（脉冲换算）：
```
# race_chassis.c:983
pulses = abs(Δmm) × 80    ← 改这个 80

# 如果走了60mm，实际只到55mm:
# 新系数 = 80 × 60/55 = 87.3
```

### 7.4 你现在的调试优先级

```
1. 修 LLM 方向（加负号）              ← 必须，否则永远调不对
2. 角度环: 从 P=0.06 开始，找最佳 P    ← 你今天能做到这步就不错了
3. 确认 MOVE/WHEEL 方向一致            ← 已经测过了，OK
4. 底盘位置: 定出准确的脉冲系数        ← 以后再说
```

## 八、角度环 PID 参数同步到比赛固件

`motor_ack_test.c` 的 LLM 调出来的参数（kp/ki/kd）和比赛固件 `race_chassis.c` 的 `PID_move()` 5组 profile 的关系：

| Profile | 比赛场景 | 默认 kp | 默认 kd | 你的 kp | 你的 kd |
|---------|---------|---------|---------|---------|---------|
| 0 (TRANSIT) | 大角度转场 | 2.0 | 0.8 | ___ | ___ |
| 1 (LOW_OUTPUT) | 低功率 | 3.3 | 1.8 | ___ | ___ |
| 3 (SETTLE_KI_LOW) | 稳态微调 | 2.0 | 0.4 | ___ | ___ |
| 4 (SETTLE_KI_HIGH) | 精确定位 | 2.0 | 0.4 | ___ | ___ |

**重要：** LLM 的 maxOutput=25，比赛的 maxOutput=180。同样的 kp 在比赛模式下输出大 7 倍。你的 LLM 参数同步到比赛固件时需要把 kp 除以约 3~4，或者保持比赛默认参数（已经调好的）。

## 九、调试步骤 —— 速度环 → 位置环 → 角度环

> 按这个顺序调：先确认底层走得通，再往上调上层。

### 9.1 速度环测试（确认四个轮子都能转、方向都对）

**目的：** 确认每个电机通电能转、方向一致、速度可控。

```
步骤1: 单轮逐个测试
  WHEEL 1 F 80 2000     ← 电机1正转 2秒
  WHEEL 2 F 80 2000     ← 电机2正转 2秒
  WHEEL 3 F 80 2000     ← 电机3正转 2秒
  WHEEL 4 F 80 2000     ← 电机4正转 2秒
  预期: 四个轮子都往同一个方向转（车前进方向）

步骤2: 正反转确认
  WHEEL 1 B 80 2000     ← 电机1反转
  预期: 和步骤1方向相反

步骤3: 整车速度矢量测试
  MOVE 0 100 0 3000     ← 前进，速度100
  MOVE 0 -100 0 3000    ← 后退
  MOVE 100 0 0 3000     ← 右移
  MOVE -100 0 0 3000    ← 左移
  预期: 四个方向都对，不偏

步骤4: 旋转方向确认
  MOVE 0 0 50 3000      ← w=50
  MOVE 0 0 -50 3000     ← w=-50
  预期: 两者方向相反，记下哪个是顺时针哪个是逆时针

步骤5: 加速度微调
  ACC 120
  MOVE 0 100 0 3000     ← 感觉起步是否平滑
  ACC 200
  MOVE 0 100 0 3000     ← 感觉是否更快，有无打滑
  记录最佳 ACC = ___

异常处理:
  某轮不转  → 查CAN地址是否对、供电是否通、驱动器是否死锁（SJ UNSTALL类）
  方向反了  → 修改 wheel_forward_dir() 返回值对调 0↔1
  车走偏    → 某轮速度和其他轮不一致，检查机械或脉冲系数
```

### 9.2 位置环测试（确认走多少距离是准的）

**目的：** 校准脉冲系数，确保命令走 N mm 实际就走 N mm。

```
步骤1: 前进100mm测试
  在地上画一条起跑线
  PULSE F 1030 200 100   ← 理论 100mm (1030 = 100 × 10.3)
  用卷尺量实际走了多少 → 记录实际距离 = ___ mm

步骤2: 修正系数
  理论: 1030 脉冲 = 100mm
  实际: 走了 ___mm
  新系数 = 10.3 × 100 / 实际距离
  例: 走了 92mm → 新系数 = 10.3 × 100/92 = 11.20

步骤3: 用新系数验证
  PULSE F 1120 200 100   ← 按新系数算 100mm × 11.2 = 1120
  再量 → 应该接近 100mm

步骤4: 大距离测试
  PULSE F 5150 200 100   ← 500mm (500 × 10.3)
  量实际距离 → 确认长距离也准

步骤5: Y方向（侧移）同样流程
  # 右移100mm: 100 × 10.5 = 1050
  PULSE F 1050 200 100   ← 但PULSE是X方向...需要用car_move_distance
  # 在PULSE命令里F是前进方向，对应Y轴
  或直接改 race_chassis.c:675 的系数后用 MOVE 命令验证

步骤6: 记录最终系数
  底盘Y方向(前进)系数: ___ 脉冲/mm  (原10.3)
  底盘X方向(侧移)系数: ___ 脉冲/mm  (原10.5)

异常处理:
  每次走的不一样 → 地面打滑或轮子空转
  前进偏左/偏右  → 某侧轮子系数不一致，单轮逐一校准
```

### 9.3 角度环测试（调 PID）

**目的：** 用 LLM 模式找到最佳 PID 参数。

**前提：** 步骤 9.1 已完成（MOVE w 方向已确认），步骤 9.2 脉冲系数不影响这个。

```
第0步: 确认方向对应
  MOVE 0 0 50 3000      ← 记下这个方向（假设是顺时针）
  MOVE 0 0 0 1
  记住: w>0 = 顺时针, w<0 = 逆时针

  然后看 PID_Calc:
    误差>0 → output>0 → 应该让yaw增大
    误差<0 → output<0 → 应该让yaw减小

  如果 LLM 跑起来方向反了 → motor_ack_test.c:871 加负号

第1步: 纯P，小角度找震荡边界
  确认 IMU 数据正常:
    IMUREAD            ← 喂IMU数据
    STATUS             ← 确认angle有值在变

  SET P:0.04 I:0 D:0   ← 从小P开始
  LLM ON 0 30           ← 原地转30°
  观察: 到了没？过冲没？
  LLM OFF

  SET P:0.06 I:0 D:0
  LLM ON 0 30
  LLM OFF

  SET P:0.08 I:0 D:0
  LLM ON 0 30
  LLM OFF

  ...逐步加大P，找到车开始来回晃的那个P值 → 震荡边界 = ___

第2步: 最佳P
  P = 震荡边界 × 0.6
  SET P:___ I:0 D:0
  LLM ON 0 90           ← 大角度验证
  LLM ON 0 -90          ← 反方向验证
  LLM OFF

第3步: 加D（如果有过冲）
  如果不加D也很稳 → 跳过此步
  如果有过冲:
    SET P:___ I:0 D:0.02
    LLM ON 0 90
    LLM OFF
    微调D（每次±0.01），找到不过冲且不肉的值

第4步: 加I（如果有残差）
  到位后角度慢慢漂走 → 加微量I
    SET P:___ I:0.02 D:___
    LLM ON 0 90
    LLM OFF
  如果反而晃了 → I太大，减半

第5步: 全方向全角度验证
  LLM ON 0 45       ← 小角度
  LLM OFF
  LLM ON 0 -45      ← 反方向小角度
  LLM OFF
  LLM ON 0 90       ← 中角度
  LLM OFF
  LLM ON 0 180      ← 大角度（最容易震）
  LLM OFF
  LLM ON 0 360      ← 一整圈
  LLM OFF

第6步: 记录参数
  STATUS
  记下: kp=___ ki=___ kd=___
  记下: ACC=___

异常处理:
  LLM ON 没反应         → IMU数据不全，先IMUREAD等几秒
  一直转不到目标就停了  → P太小，加大
  到位后猛烈晃          → P太大，减半
  穿过目标又弹回来      → 加D
  到位后慢慢漂走        → 加I
  大角度震、小角度稳    → P对大角度偏大，稍降P或用小角度P
```
