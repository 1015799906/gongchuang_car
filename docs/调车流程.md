# 完整调车流程

> 从零开始，把一台新装/维修后的机器人调到比赛状态。
> 前提：机械结构已安装完成，接线正确，调试器和串口线已连接。

---

## 调车总览

```
阶段1  [30min]  环境准备 —— 接线确认、串口连通、首次烧录
阶段2  [60min]  单项硬件验证 —— 逐项测试每个执行器
阶段3  [60min]  回零标定 —— 平推/升降碰撞回零方向确认
阶段4  [90min]  位置标定 —— 平推/升降/云台/舵机的位置值标定
阶段5  [60min]  底盘标定 —— 编码器系数、PID参数、直线行驶
阶段6  [60min]  动作组联调 —— 完整动作链验证
阶段7  [90min]  视觉标定 —— 颜色阈值、霍夫圆参数、坐标映射
阶段8  [60min]  整机联调 —— 上下位机联调、完整任务流程
阶段9  [30min]  比赛固件验证 —— 烧录主固件，整流程跑一遍
```

---

## 阶段1: 环境准备

### 1.1 接线确认清单

```
□ DAPLink 连接 STM32 的 SWD (SWCLK + SWDIO + GND)
□ DAPLink USB 插电脑
□ USB转串口 连接 STM32 UART5 (PC12=TX, PD2=RX, GND)
□ USB转串口 USB 插电脑
□ 24V 电池/电源 → 电机驱动供电
□ STM32 板供电正常
□ 舵机独立供电正常
□ CAN总线终端120Ω电阻在位
```

### 1.2 确认串口

**打开设备管理器** → 端口 → 找到 USB转串口 对应的 COM 号，记下来。

后面所有串口终端操作都对着这个 COM 口，**波特率 115200, 8N1, 无流控**。

### 1.3 首次构建 motor_test 固件

```bash
cd STM32f407_wuliu_motor_test
# 如果还没配置过 CMake：
./cfg.sh
# 构建
./build.sh
```

### 1.4 烧录

```bash
./flash.sh
```

**预期输出：**
```
Programming Finished
Verified OK
Resetting Target
```

### 1.5 打开串口终端

用你习惯的串口工具（推荐 PuTTY 或 VS Code 内置的 Serial Monitor）打开对应 COM 口，115200-8-N-1。

### 1.6 验证通信

上电后，串口终端应该立即收到启动状态信息。

**手动输入以下命令验证：**
```
STATUS
```

**预期返回：** 当前舵机PWM、软件位置、IMU角度、PID参数等状态信息。

如果没有响应：
- 检查 TX/RX 是否接反（交叉试试）
- 检查波特率是否为 115200
- 检查板子供电是否正常
- 检查固件是否烧录成功

## 阶段2: 单项硬件验证

> **安全原则：每次测试新执行器前，先确认急停命令有效。**

### 2.1 舵机验证

#### 夹爪 (CH2)

```
ZH 50               ← 应该听到舵机转动，夹爪打开
ZH 25               ← 夹爪闭合
ZH 50               ← 再打开，确认动作正常
```

**检查项：**
- □ 开爪方向正确（张开，不是闭合）
- □ 合爪方向正确（闭合，能夹住物块）
- □ 25° 夹紧力足够，50° 完全张开

**如果方向反了：** 交换开爪/合爪的角度值。

#### 置物盘 (CH3)

```
PT 0                ← 位置1，记下此时物理方向
PT 135              ← 旋转约半圈
PT 270              ← 再转半圈
PT 0                ← 回到位置1，确认转回原位
```

**检查项：**
- □ 三个位置都能准确到达
- □ 旋转方向正确
- □ 位置1→位置1 能转回原位（没有累积误差）

#### 云台 (CH4)

```
YT 0                ← 置物架方向（记下物理朝向）
YT 90               ← 右环方向
YT 120              ← 中心环方向
YT 150              ← 左环方向
YT 0                ← 回到置物架方向
```

**检查项：**
- □ 90° 对应右环方向
- □ 120° 对应正中心
- □ 150° 对应左环方向
- □ 旋转方向与实际场地环位置一致

### 2.2 平推电机验证

> **⚠️ 这是最容易出问题的环节，务必小心！**

```
PUSH ZERO           ← 先把软件位置标零
PUSH 5 400 60       ← 目标5mm，速度400，加速度60

# 观察物理运动方向：
# 正确：平推手向外伸出
# 如果向内收回 → 方向反了！立即 PUSH STOP
```

```
PUSH 0 400 60       ← 回收
PUSH STOP           ← 急停测试（确认急停有效）
```

**检查项：**
- □ 正数方向 = 向外伸出
- □ 急停有效
- □ 运动平滑，无异响

**如果方向反了：**
1. 断电
2. 找到平推电机的 CAN 地址配置
3. 交换 `dir` 参数（0↔1）
4. 重新构建烧录

### 2.3 升降电机验证

> **⚠️ 同样容易出问题！**

```
SJ ZERO             ← 先标零
SJ 5 400 60         ← 目标5mm

# 观察物理运动：
# 正确：升降机构向下运动
# 如果向上 → 方向反了！立即 SJ STOP
```

```
SJ 0 400 60         ← 回到标零位
SJ STOP             ← 急停测试
```

**检查项：**
- □ 正数方向 = 向下运动（离开顶部零点）
- □ 急停有效
- □ 行程范围内无卡死

### 2.4 底盘电机验证

```
ACC 160             ← 设置加速度

# 需要 calib 模块支持。如果用纯 motor_test：
# 先确认 CAN 通信正常：
STATUS              ← 查看是否报告 CAN 状态
```

如果 `motor_ack_test` 包含 `chassis_calib` 的单字符命令：
```
V                   ← 四个轮子同时正转（前进）
0                   ← 立即停止
W                   ← 原地旋转
0                   ← 停止
```

**检查项：**
- □ 四个轮子都转
- □ 前进方向正确
- □ 旋转方向正确
- □ 无异常噪音

### 2.5 IMU 验证

```
IMU
```

**预期返回：** Yaw/Pitch/Roll 三个角度值。

**检查项：**
- □ 手动旋转机器人，Yaw 角度随之变化（变化连续，不跳变）
- □ 三个角度的更新频率正常

### 2.6 加热验证

```
ACT HEAT ON         ← 开启加热，PWM=300
# 观察加热端是否发热（用手靠近感受，别摸！）
ACT HEAT OFF        ← 关闭加热
```

## 阶段3: 回零标定

### 3.1 平推回零

> **这一步定死了平推的物理零点位置，一旦确定不要再改。**

```
PUSH HCFG 0         ← 查看当前回零配置（方向CW/参数）
PUSH HOME           ← 执行碰撞回零

# 观察：
# 平推应朝物理零点（回收方向）缓慢运动
# 碰到机械限位后自动停止
# → 成功：状态显示 idle
# → 方向反（向外冲）：立即 PUSH HSTOP → 断电
```

**成功后：**
```
PUSH CLEAR          ← 清零驱动器位置
PUSH ZERO           ← 清零软件位置
PUSH READ           ← 确认位置归零 pos=0
```

**如果 HOMEZERO 方向反了：**
```
# 切换方向
PUSH HCFG 1         ← 改为 CCW 方向
PUSH HOME           ← 重新执行
```

### 3.2 升降回零

```
SJ HCFG 0           ← 查看当前配置（dir/current/time）
SJ HOMEZERO         ← 执行碰撞回零（应向上到顶）

# 观察：
# 升降应向上碰到顶部机械限位
# 碰到后自动停止
# → 成功：显示 DONE
# → 方向反（向下冲卡死）：立即 SJ HSTOP → 断电
```

**成功后：**
```
SJ CLEAR            ← 清零
SJ ZERO             ← 软件清零
SJ READ             ← 确认 pos=0
```

**如果碰撞电流阈值不合适：**

碰到后不停止（电流阈值太高）→ 降低：
```
SJ HCFG 1 400 20    ← dir=CCW, current=400mA, time=20ms
SJ HOMEZERO         ← 重新执行
```

没碰到就停了（电流阈值太低）→ 提高：
```
SJ HCFG 1 800 50    ← current=800mA, time=50ms
```

### 5.2 PID姿态参数调优

```
# 重置 PID
SET P:1.5 I:0 D:0.5

# 测试1: 小角度旋转
LLM ON 0 45                 ← 原地转45度
# 观察: 到位快不快？过冲吗？来回晃吗？
LLM OFF

# 测试2: 大角度旋转
LLM ON 0 180                ← 原地转180度
# 观察: 大角度表现
LLM OFF
```

**PID调整策略:**

| 症状 | 调整方向 | 示例 |
|------|----------|------|
| 到位太慢 | 加大 P | `SET P:2.5 I:0 D:0.5` |
| 过冲严重 | 加大 D 或减小 P | `SET P:1.5 I:0 D:1.0` |
| 到位后来回晃 | 加大 D | `SET P:1.5 I:0 D:1.5` |
| 有稳态误差 | 加大 I | `SET P:1.5 I:0.05 D:0.5` |
| 到位快但震荡 | 减小 P, 加大 D | `SET P:1.2 I:0 D:1.0` |

**找到每组最优参数后，分别测试5种Profile对应的角度：**
```
LLM ON 0 90     ← Profile 0 (TRANSIT) 场景: 90度转场
LLM ON 0 180    ← Profile 0 场景: 180度转场
LLM ON 0 10     ← Profile 3 (SETTLE_KI_LOW) 场景: 微调
LLM ON 0 5      ← Profile 4 (SETTLE_KI_HIGH) 场景: 精定位
```

**记录各组PID参数。**

### 7.3 霍夫圆参数标定

> 用 `--ring` 或 `--ring-preview` 模式，确认圆检测效果。

**调整参数：**
```python
circles = cv2.HoughCircles(
    gray, cv2.HOUGH_GRADIENT,
    dp=1,
    minDist=30,        # ← 两圆最小间距
    param1=50,          # ← Canny高阈值（降=多检测）
    param2=30,          # ← 圆心阈值（升=更严格）
    minRadius=35,       # ← 最小半径px
    maxRadius=45        # ← 最大半径px
)
```

**判定标准：**
- 物块圆正确检测出来（不被漏检）
- 没有误检（把非圆的东西当圆）
- 半径范围正确

### 7.4 坐标映射标定

**目标：** 验证上位机返回的坐标 → STM32物理坐标的转换准确性。

**方法：**
1. 在已知物理位置放一个物块（用尺子量好x,y坐标）
2. 运行视觉任务，看返回的坐标
3. 让 STM32 根据返回坐标运动，用尺子量实际到达位置
4. 计算误差，调整比例尺

**STM32侧调整位置：**
```
race_task.c 中的 bilichi 公式:
  bilichi = -0.0035f * (distance + 80.0f) + 1.1967f;  ← 调整系数
  bilichi = -0.0033f * distance + 1.1655f;             ← 调整系数

race_task.c 中的坐标偏移:
  x_origin -= 322.0f;   ← 摄像头X偏移（像素→mm）
  y_origin -= 165.0f;   ← 摄像头Y偏移（像素→mm）
```

| 视觉误检 | 光照变化 | 放宽颜色HSV阈值 |
| 动作组碰撞 | 转移高度不够 | 加大 ACT_H_TRANSFER |
| 加热不热 | PWM太小 | 加大 ACT_HEAT_COMPARE |
| 底盘走偏 | 编码器系数不准 | 重新标定 10.5/10.3 |
| 串口通信断 | 线松或波特率不匹配 | 检查接线和设置 |

```

  □ DAPLink连接可靠

  □ 上电后无异常发热/异味
```
