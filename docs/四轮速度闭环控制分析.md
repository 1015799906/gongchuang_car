# 四轮速度闭环控制分析

---

## 一、当前状态：全开环

```
LLM 目标角度 ─→ PID_Calc() ─→ move_vel() ─→ move_vel()
                                              ├─ speed[1]=-vx+vy-w → zdt_vel(1,...) ─→ CAN ─→ 电机
                                              ├─ speed[2]=+vx+vy+w → zdt_vel(2,...) ─→ CAN ─→ 电机
                                              ├─ speed[3]=+vx+vy-w → zdt_vel(3,...) ─→ CAN ─→ 电机
                                              └─ speed[4]=-vx+vy+w → zdt_vel(4,...) ─→ CAN ─→ 电机

zdt_vel() 一发完就返回。电机实际转没转、转速对不对 —— 不知道。
```

`zdt_vel()` 是单向指令（命令码 0xF6），电机驱动收到后执行但**不作回报**。LLM 控制回路唯一的反馈是 IMU 的 Yaw 角——这是角度环，不是轮速环。

---

## 二、电机驱动的两层控制

ZDT 电机驱动（CAN 地址 1~6）内部自带闭环：

```
┌─────────────────────────────────────────────────────────────┐
│  ZDT 电机驱动                                               │
│                                                             │
│  zdt_vel(0xF6) ─→ 速度指令 ─→ [速度PID] ─→ 电流环 ─→ 电机  │
│                    ↑                        │               │
│                    │        编码器反馈 ←─────┘               │
│                                                             │
│  zdt_pos(0xFD) ─→ 位置指令 ─→ [位置PID] ─→ 速度环 ─→ 电流  │
│                    ↑                        │               │
│                    │        编码器反馈 ←─────┘               │
└─────────────────────────────────────────────────────────────┘
```

驱动内部的 PID 参数可以通过 `zdt_read(addr, ZDT_S_PID)` 读取（命令码 0x21），但当前固件没有提供写入 PID 的函数。如果驱动内部速度环的参数没有调好，发出去的 `zdt_vel()` 实际转速可能不准。

### STM32 能查什么

| 查询 | 含义 | 用途 |
|------|------|------|
| `zdt_read(addr, ZDT_S_VEL)` | 当前实际转速 (RPM) | 轮速闭环反馈 |
| `zdt_read(addr, ZDT_S_CPOS)` | 当前位置 (脉冲) | 里程计、速度计算 |
| `zdt_read(addr, ZDT_S_PERR)` | 位置跟踪误差 | 判断是否跟丢 |
| `zdt_read(addr, ZDT_S_FLAG)` | 状态标志 | 堵转/到位/故障检测 |

## 三、两套闭环架构

### 方案A：信任驱动内部速度环（调参为主）

**思路**：轮速闭环交给电机驱动做，STM32 只发目标速度。调优驱动内部的 PID 参数，让 `zdt_vel()` 发出去后每个轮子实际转速接近一致。

**需要的步骤**：
1. 通过 `zdt_read(ZDT_S_PID)` 读取当前驱动 PID 值
2. 找到修改驱动 PID 的方法（驱动厂家工具、或者补写 `zdt_write_pid()` 函数）
3. 逐个轮子测试：发 `zdt_vel()`，读 `zdt_read(ZDT_S_VEL)`，对比目标 vs 实际

**优点**：
- 不改控制架构，不占 STM32 CPU
- 驱动内部速度环跑得快（可能 1kHz），比 STM32 用 CAN 查询快得多

**缺点**：
- 依赖驱动内部参数，需要驱动厂家的调参工具或协议文档
- 如果驱动内部速度环本身就弱，则无法改善

---

### 方案B：STM32 做外环速度控制

**思路**：STM32 在每个控制周期内，读四个轮子的实际速度，和目标速度做差，用 PID 修正速度指令。

**数据流**：

```
                             ┌── 编码器 ←──┐
麦轮逆运动学                  │             │
vx,vy,w → speed[1..4]       │             │
             │               │             │
             ├───→ zdt_vel(速度目标) ──→ CAN ──→ 电机驱动 ──→ 电机
             │                                          
             ├───→ zdt_read(VEL) ←── 查询实际转速 ←── CAN 返回
             │         │
             │    ┌────┴────┐
             │    │ speed_PID│  ← 对每个轮子: 目标转速 vs 实际转速
             │    │  P × err │
             │    └────┬────┘
             │         │
             └──── 修正后的速度 ──→ zdt_vel(新的速度指令)
```

**伪代码**：

```c
// 每个控制周期（例如 10ms 一次）
void wheel_speed_loop(void)
{
    float target_rpm[5];   // 麦轮解算后的目标转速
    float actual_rpm[5];   // 从编码器读回的实际转速
    float corrected[5];    // PID修正后的输出

    // 1. 麦轮逆运动学：vx,vy,w → target_rpm[1..4]
    target_rpm[1] = -vx + vy - w;
    target_rpm[2] = +vx + vy + w;
    target_rpm[3] = +vx + vy - w;
    target_rpm[4] = -vx + vy + w;

    // 2. 查询每个电机的实际转速
    for (id = 1; id <= 4; id++) {
        zdt_read(id, ZDT_S_VEL);
        delay_us(500);  // 等 CAN 回报
        actual_rpm[id] = parse_vel_from_can_rx();  // 从CAN接收帧解析
    }

    // 3. 每个轮子跑独立的速度PID
    for (id = 1; id <= 4; id++) {
        float error = target_rpm[id] - actual_rpm[id];
        wheel_pid[id].integral += error * ki * dt;
        // 积分限幅
        float output = target_rpm[id]  // 前馈（开环速度指令）
                     + error * kp       // P项修正
                     + wheel_pid[id].integral;  // I项消静差

        corrected[id] = clamp(output, -MAX_RPM, MAX_RPM);
    }

    // 4. 发修正后的速度
    for (id = 1; id <= 4; id++) {
        wheel_vel(id, (int32_t)corrected[id]);
    }
}
```

**关键点**：
- **前馈**是必须的——PID 输出叠加在开环速度指令上，不替代它。如果只用 PID 输出（没有前馈），响应会非常慢，因为 P 项从零开始积累。
- **I 项要限幅**，防止积分饱和。
- CAN 查询轮速的延时是瓶颈——4 个电机、每个 1~2ms 回报，一个循环要 4~8ms。要在速度带宽和 CPU 负载之间做取舍。

## 四、调参流程

### 4.1 先标定转速 → 编码器脉冲的换算关系

```
zdt_vel(addr, dir, 500, acc, false);   // 发 500 RPM
delay_ms(200);                          // 等转速稳定
zdt_read(addr, ZDT_S_VEL);             // 读回报的实际 RPM
```

对比 4 个轮子，记录每个轮子在不同指令转速下的实际转速，画一张表：

| 指令 RPM | 轮1实际 | 轮2实际 | 轮3实际 | 轮4实际 |
|----------|---------|---------|---------|---------|
| 200 | ? | ? | ? | ? |
| 500 | ? | ? | ? | ? |
| 1000 | ? | ? | ? | ? |
| 1500 | ? | ? | ? | ? |

如果某个轮子实际转速明显偏低（差 10% 以上），优先排查机械（轴承卡滞/轮子摩擦），再考虑驱动内 PID 不一致。

### 4.2 调速度环 P 增益

从 **P=0.1** 开始。不发前馈，只发纯 P 修正：

```
目标转速 500rpm，实际 450rpm → error = 50
输出 = 50 × 0.1 = 5 → 发 505 rpm
```

每次翻倍：

```
P=0.1   → 看实际转速能不能逼近目标？差多少？
P=0.2   → 更接近了？
P=0.4   → 开始振荡了？（实际转速在目标附近来回跳）
```

出现振荡时，往回退一步。取振荡前那个 P 值的 70% 作为最终 P。

### 4.3 加前馈

P 值定好后，打开前馈：

```
输出 = 目标转速 + P × error
```

前馈让速度指令直接包含目标值，PID 只修正误差。这样做的好处：
- 指令变化时，前馈立刻响应（不经过 P 项积累）
- P 项只负责纠偏，不需要很大的增益
- 系统更稳定

### 4.4 决定要不要 I 项

对于麦轮底盘，I 项通常**不需要**，因为：
- 轮速偏差会被底盘整体偏转（IMU Yaw 角）检测到，LLM 角度环会纠正
- 加 I 项容易在堵转时积分饱和，导致松脱后突然猛转

但如果想精确走直线（比如 `MOVE 0 1000 0`），I 项可以消除轮间速度差异导致的缓慢偏移。加 I 时从 `ki=0.01` 起步，必须加积分限幅。

## 五、时间规划

### 调参时间表

| 步骤 | 预计耗时 | 说明 |
|------|---------|------|
| 4轮转速标定 | 15分钟 | 每轮测 4 个速度点，记录实际值 |
| 调驱动内部PID | 30分钟 | 如果驱动内部PID不一致，需逐个调平 |
| 调STM32速度环P | 20分钟 | P从小到大，找到振荡临界点 |
| 加前馈+验证 | 10分钟 | 打开前馈，测全速范围响应 |
| 联调LLM角度环 | 20分钟 | 速度环调好后，需重新调LLM的kp/ki/kd |
| 合计 | ~1.5小时 | |

### 关键经验

1. **先保证机械一致**：四个轮子阻力相等。用手转每个轮子感受阻力差。阻力大的先排查轴承、皮带。
2. **驱动内部速度环先调平**：`zdt_vel(500)` 四个轮子实际转速应一致（±5%）。不一致时优先调驱动参数，不要依赖 STM32 外环硬纠。
3. **CAN 查询频率别太高**：CAN总线 500kbps 被 6 个电机共享。LLM 模式下已经有 `zdt_vel()×4`（4 帧/50ms），再加 `zdt_read()×4`（4 帧查询 + 4 帧回报 = 8 帧/50ms），总线负载翻倍。建议速度环周期降到 20~30ms，甚至只在 LLM 不激活时跑。
4. **速度环和角度环是级联的**：速度环在内层（快），角度环在外层（慢）。速度环带宽必须 > 角度环带宽。大概比例：速度环 50Hz，角度环 20Hz。
5. **万用表+示波器辅助**：如果怀疑电机驱动不响应，用 CAN 分析仪抓包确认指令发出、回报收到。

## 六、和现有LLM角度环的关系

```
                    ┌─────────────┐
    目标角度 ──────→│  LLM角度环   │────→ vx,vy,w ────┐
    实际角度 ←──────│ (PID_Calc)   │                    │
                    └─────────────┘                    ↓
                                               ┌─────────────┐
                                               │ 麦轮逆运动学 │
                                               │  move_vel()  │
                                               └──────┬──────┘
                                                      │ speed[1..4]
                                                      ↓
                    ┌─────────────┐          ┌─────────────┐
  实际转速 ←───────│  zdt_read()  │←────────│  速度闭环    │←── 新增
  目标转速 ───────→│  PID校正     │────────→│  zdt_vel()   │
                    └─────────────┘          └─────────────┘
```

角度环是外环，输出 `vx,vy,w`。速度环是内环，接收 `speed[1..4]`，保证实际轮速跟踪目标轮速。

**角度环 kp 和速度环 P 不能同时调。** 先关掉 LLM（角度环），用 `MOVE` 开环测速度环。速度环调好后，再开 LLM 调角度环。
